# quarto2 PyPI package: developer notes

`README.md` in this directory is the PyPI project description. This file is
for maintainers. Strand bd-2p7dwmqe; design in
`claude-notes/plans/2026-11-13-pypi-publishing.md`; release procedure in
`claude-notes/instructions/release-runbook.md` (section "PyPI").

## Layout

| Path | Role |
|---|---|
| `pyproject.toml` | Points build frontends at the in-tree backend; `requires = []`. |
| `backend/q2_pypi_backend.py` | PEP 517 hooks: `build_sdist`, `build_wheel`, `prepare_metadata_for_build_wheel`. |
| `backend/q2_pypi_lib.py` | Platform mapping, version mapping, checksum pins, download/verify/extract; also the `prepare` CLI. |
| `quarto2/` | The importable package: `binary_path()`, `python -m quarto2`. |
| `tests/` | `unittest`, stdlib only, offline (fake release served via `file://`). |
| `release.json`, `LICENSE` | Generated by `prepare`; gitignored. |

The sdist holds no binary. `build_wheel` runs on the installing machine,
downloads that host's archive from the GitHub Release, checks it against
`release.json`, and writes a `py3-none-<host>` wheel with the binary in
`.data/scripts/`, so the installed `q2` is the native executable.

## Run the tests

```bash
python3 -I -m unittest discover -s packaging/pypi/tests   # from the repo root
```

`cargo xtask verify` runs the same command in step 1 (`--skip-pypi-tests`
to skip); CI runs it in `.github/workflows/pypi-package.yml`.

## Try a real release locally

```bash
cd packaging/pypi
gh release download v0.45.0 --repo quarto-dev/q2 -p checksums.sha256 -D /tmp/q2rel
python3 -I backend/q2_pypi_lib.py prepare --tag v0.45.0 \
  --checksums /tmp/q2rel/checksums.sha256 --license ../../LICENSE
uv build --sdist -o /tmp/q2rel/dist .
python3 -m venv /tmp/q2rel/venv
/tmp/q2rel/venv/bin/pip install /tmp/q2rel/dist/quarto2-0.45.0.tar.gz
/tmp/q2rel/venv/bin/q2 --version
```

`QUARTO2_DOWNLOAD_BASE` points downloads at a mirror (or a `file://`
directory laid out as `<base>/<tag>/<archive>`).
