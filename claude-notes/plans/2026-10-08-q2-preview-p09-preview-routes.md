## Background facts

(Line numbers from the 2026-10-08 survey; re-check.)

- **Existing route.** `POST /api/preview/render` (`quarto-preview/src/render_download.rs`, registered in `extend_with_preview`, `lib.rs:737`) calls `render_to_file(abs_path, format, &RenderToFileOptions{ output_dir: Some(temp), execution_policy: None, source_override: content, quiet })` inside `spawn_blocking`. The caller's format key beats the document's own `format:`. `FORMATS` omits `typst` (`render_download.rs:43-56`) and `odt` (it exists in `PANDOC_FORMATS`, `quarto-core/src/pandoc_request/formats.rs:31`; no reason is recorded, so it is an omission). The route hard-codes `ExecutionPolicy::None` and drops everything but diagnostics (`:136`). `renderNatively` (`hub-client/src/pandoc/nativeRender.ts`) already parses `{error, diagnostics}` (`:61-64`) and maps every non-ok response to `native-error`.
- **Finding a capture.** The preview handlers receive `State<SharedContext>`; `ctx.index().get_capture(path)` returns the sidecar entry with `capture_doc_id` (`capture_driver.rs:602`) and `read_capture_from_doc(&ctx, &id)` reads it and accepts older single-object captures (`:388`). It accepts any doc id, so the id must come from the sidecar for the request's path, never from the client. Sidecar keys are hub-root-relative (`pandoc_request/captures.rs:67`; `sidecar_key_from(root, path)` at `:47` is pure and takes the root; the hub root is `ctx.storage().project_root()`, quarto-hub `storage.rs:603`, not in core). A canonical `project.dir` against a non-canonical hub root silently yields a wrong key ("no capture"), so canonicalize the root first.
- **Attribution.** Native `attribution` honours only `Git` (`render_to_file.rs:371-381`); the wasm side installs a client-built `PreBuiltAttributionProvider` (`attribution/prebuilt.rs`). The native option carries the payload as a JSON `String` and `render_to_file` builds the provider from it.
- **Fonts.** Brand Google fonts are downloaded (`typst_google_fonts.rs`) into `<project>/.quarto/typst/fonts`; a `/render typst-pdf` download and a preview can overlap.
- **Injection points.** `SharedContext = Arc<HubContext>` (`quarto-hub/src/context.rs:956`) has no extension slot, and `extend_with_preview` is passed as a bare fn pointer (`quarto-preview/lib.rs:497`); the precedent for process-wide state in this crate is a static (`re_execute.rs` `CACHE_DIR`, `IN_FLIGHT`). `render_download.rs:349` builds the router with `extend_with_preview(Router::new())`, so the test seams are statics too (tests that swap one run under nextest's process-per-test).
- **Options struct.** `RenderToFileOptions` derives `Debug, Clone, Default` (`render_to_file.rs:84`); `AttributionSourceProvider: Send + Sync` has no `Debug` bound (`attribution/source.rs:35`), so a trait-object field would not compile.
- **Books.** Chapter-alone and whole-book requests are Plan 3's `resolve_book_scope` and Plan 10's book entry; this plan only resolves scope and calls a seam for `Book`.
- **Concurrency.** `re_execute`\'s `IN_FLIGHT` is a static synchronous `HashSet` (`re_execute.rs:46`), 409-only and not reusable; tokio has the `sync` feature (`quarto-preview/Cargo.toml:12`), so a `Notify`-based slot is implementable; no `DefaultBodyLimit` exists anywhere in `crates/`, so axum's implicit 2 MB applies today.
- Runtime requirements: native `typst` (>= 0.8) and `pandoc` are external (`Q-21-1`, `Q-20-1`, `Q-20-2`); five `@preview` packages are vendored and any other `@preview` import is downloaded on every render (+0.35 s, the package cache is per render); `typst-gather` writes progress to stderr with no verbosity parameter (cross-repo follow-up).

## Decisions

- **P9-D1 One mechanism for the embed (E1).** Native routes; they never launch kernels (`ExecutionPolicy::None` plus the AST capture splice). Two routes, one helper: `POST /api/preview/pdf` is the inline, supersede-aware PDF route; `POST /api/preview/render` is the attachment route (no supersede) and takes format keys from the same Rust table. Both use `typst_target: Pdf` for the `typst-pdf` key (E8), and set `RenderToFileOptions.cancellation` (a drop guard on the handler future) and `child_deadline` (a named constant, 120 s to start; measure against the orange-book, which takes about 2 s) so Plan 1's runner bounds and cancels the children, so a doc with a non-`pdf` `output-ext` still yields a PDF as in hub-client; the `typst` key uses `typst_target: Source`. The `typst-pdf` key maps to render format `typst` explicitly (there is no render-format column in `PANDOC_FORMATS`).
- **P9-D2 Content.** The client sends the document text as `content` (the disk copy is stale in `--ui editor` without `--allow-edit`); the path anchors project discovery and relative resources; nothing is written back. A caller that omits `content` must not get a blank document: `Some("")` is an explicit empty source, so a missing field means "read the disk copy".
- **P9-D3 Authorship.** The client sends `attributionJson` built by the same `attributionJsonFor` as the wasm path (Automerge history, hub identities); git blame is the wrong source. Measure payload size on a long history and set an explicit body limit.
- **P9-D4 Captures (E10).** Resolved server-side from the sidecar for the request's path; no capture ids on any request; a missing, failed or `Off`-policy entry compiles unexecuted and reports the notice.
- **P9-D5 Scope.** Request `scope?: 'book' | 'chapter'` (absent is `None`; `/pdf` always sends `chapter`), resolved with `resolve_book_scope` (P3-D2). Resolved `Chapter` calls `render_chapter_alone`; resolved `Page` calls `render_document_to_file` (with the notice in `X-Q2-Diagnostics` when P3-D2 says so); resolved `Book` calls the book seam (9.6). An explicit scope for a non-consolidating format is ignored with the info diagnostic.
- **P9-D6** Multi-format documents: first declared format wins, no picker. Missing typst/pandoc shows the existing `Q-21-1` / `Q-20-1`/`Q-20-2` text; bundling typst is out of scope.
- **P9-D7 Share trust.** Any join-string holder can already POST native renders (the tunnel is a raw TCP copy, `quarto-p2p/src/host.rs:191-208`); accepted and documented in Plan 13.
- **P9-D8 Table-driven formats.** The route's `FORMATS` becomes a lookup in `PANDOC_FORMATS` (key, render format, extension, MIME), and the client's menu follows the same rule through `getPandocFormats()` plus one `nativeSupported` rule (Plan 12), so the two cannot drift.

## Route contract (shared by `/api/preview/pdf` and `/api/preview/render`)

Request `{path, content?, scope?, attributionJson?}`. 400 bad path; 422 `{error, diagnostics}` with structured diagnostics for a failed render (match `QuartoError::Parse`, `pipeline.rs:1318-1325`); 200 with `X-Q2-Diagnostics` for warnings and `X-Q2-Stats` (percent-encoded JSON `{"unexecuted_cells": N}`; Plan 10 adds `book`); 409 with body `{"superseded": true}` (`/pdf` only) or `{"busy": true}` (Plan 10); an explicit per-route `DefaultBodyLimit` (8 MB). `/api/preview/pdf` returns `application/pdf` without `Content-Disposition`; `/render` returns an attachment. Per-path latest-wins slot for `/api/preview/pdf` only: normalized path key; waiters wait asynchronously (`Notify`), only the winner calls `spawn_blocking`, never a waiter on a blocking-pool thread; the slot guard is owned by the handler until `spawn_blocking`, then moved into the closure, and released when the `spawn_blocking` task finishes, not when the handler future drops; at most one render per path; a request replaced while waiting, or while its render is already running, returns the superseded 409 (the running render's cancellation is set, so Plan 1's runner kills its child, and its result is discarded). `/render` downloads never supersede. No result cache.

- Typst diagnostics\' line numbers refer to the intermediate `.typ`; source mapping is out of scope.
