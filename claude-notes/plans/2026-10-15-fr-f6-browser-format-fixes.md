## Goal

In hub-client, a chapter with no front-matter `format:` of a project whose `_quarto.yml` says `format: typst` gets the PDF pane, and a project-level `format: revealjs` page previews as slides. Every wasm entry that used to read the format from the document's own front matter calls the resolver instead, with the editor buffer and the project from the VFS. The wasm result keeps the full key list.

## Decisions

All from the epic; the plan-level ones:

- **F6-D1 One call, in Rust, keeping the key list and the book information.** The existing `resolve_pandoc_formats` is extended (not replaced by a single-key function) to take the editor buffer as `content_override`, and to return, besides `formats[]`, the resolved `key`, its **`class`**, the `pseudoFormat` and the resolved scope; it calls `resolve_document_format` with the preview's request (chapter scope: FR13) and the project from the VFS. The `book` field the Download menu reads stays as it is (computed from membership as today; only the *format decision* is chapter-scoped, so F6-D5's "menu unchanged" holds). Every wasm entry that built a format from `detect_format_from_content` now gets its format from the same resolution; `detect_format_from_content` is deleted. **Shape the parameters as an options object** (`{ contentOverride?, to?, metadata? }`, with only the first used here): F8 later adds the requested format (`--to`) and the CLI's metadata to the same call, and must not have to change every caller again.
- **F6-D2 `parse_qmd_to_ast` stays front-matter-only; the resolved key, not `formats[0]`.** It has no path, so it does not decide the format. `parse_qmd_to_ast_with_attribution` (call site `:870`) also stays front-matter-only: it reads the document's own format keys with F2's front-matter helper (`frontmatter_format_keys` is deleted in F3a, so it is not available). F2's collector module is not cfg-gated (`pandoc_request/formats.rs`, which is compiled for wasm, already calls it through `output_ext`), so the helper is available to the wasm crate; 6.2's wasm check proves it. `classifyPreviewMode` calls the resolver (through the extended function) **before** `getQ2Format`\'s early return for html, and uses the Rust-resolved key and class plus the existing mode classification; `getQ2Format`, the SPA's `isTypstPdf` and the PDF-pane gating read the resolved `key`/`class`, never `formats[0]` (with a requested `to` that is not declared, `formats[0]` is wrong, F8). TypeScript decides nothing about the format. The wasm tests that call `parse_qmd_to_ast` keep working unchanged. The pseudo-format mapping stays where it is except where this plan's call sites make a duplicate dead (then delete it); otherwise leave it (FR19). Moving the call before the html early return means every html keystroke now calls the resolver, which is why F6-D3's cache matters.
- **F6-D3 Project discovery is cached against a generation counter that moves only when it should.** Resolving on every keystroke must not re-parse `_quarto.yml` each time: cache the discovered project in wasm, keyed by **the discovered project directory plus a generation counter** (`discover(path)` depends on the path's ancestors, so the path alone is not the key). The counter lives **inside `VirtualFileSystem`** (`quarto-system-runtime/src/vfs.rs`: `add_file`, `add_file_if_changed`, `remove_file`, `add_directory`, `remove_directory`, `clear`, `clear_preserving_prefix`), not in `WasmRuntime`\'s wrapper methods, because `with_vfs_mut` hands callers `&mut VirtualFileSystem` and the wrappers are bypassed. The rule is an exclusion list, not an allow-list of config files: **a write does not bump only if it is a content edit of an *existing* `.qmd`, `.md` or `.ipynb` (the keystroke case), or its path is under `/.quarto/` or `/__quarto_resources__/` (artifact flushes, which create files there); everything else bumps**: a create or remove of any other path, any config file (`_quarto.y*ml`, `_metadata.y*ml`, `_brand.y*ml`), the brand file the `brand:` key names (`ProjectContext::parse_config` resolves it through `quarto_sass::resolve_brand`, `project/mod.rs:2407`, so a custom-named brand file is on no allow-list), anything under `_extensions/`, and every `clear*`. A replace is told from a create by `self.files.insert(..)` returning `Some` or `None`. 6.2 first reads how `vfsAddFile` is called for an existing file (and the sync client's `onFileChanged`, which round 5 did not read) and records it. Measure `resolve_pandoc_formats` and `parse_qmd_to_ast` latency before and after on a book project against the **release + wasm-opt artifact** that `npm run test:wasm` runs (`vitest.wasm.config.ts`, `build-wasm.js:160-170, 185`; `performance.now()` inside a `*.wasm.test.ts` is enough; use the same artifact for both numbers) and report both; no regression gate, but a large one is a stop-and-ask.
- **F6-D4 Buffer, not VFS.** The resolver reads the open file's front matter from the buffer the router parsed (the content override, F2-D3), not the VFS copy. If the buffer and the VFS differ, the buffer wins. `PreviewRouter` passes the buffer text.
- **F6-D5 The Download menu is unchanged.** Its entries and behaviour stay as they are; the menu keeps reading the full `formats[]` and `book`. A vitest pins the entries for a typst book (book and chapter entries) so a later change is visible.

## Risks

- Wasm builds only with the C toolchain env from `dev-docs/wasm.md`; do not skip the check, and rebuild the artifact before running the wasm tests.
- `lib.rs` and the hub-client routing files are hot; F4 just touched the request options in the same file.
- Resolving on every keystroke is the performance risk (F6-D3); keep the cache simple and per generation, and make sure the counter is not bumped by the keystroke path.
- Changing `resolve_pandoc_formats`\'s result shape is a cross-language change: the `.d.ts`, `wasmRenderer.ts` and every TS caller change in the same plan.
- Known limitation, not changed here (`bd-html-chapter-xref-szfxmvyg`): an html chapter rendered alone leaves cross-chapter `@refs` unresolved on the native path, and by code reading the browser's ActivePage path has the same gap (not executed). F6 only fixes which format is chosen.
- The generation counter's rule is an exclusion list (only content edits of existing documents and artifact writes are free), so a mistake errs towards a cache miss, never a stale project; the cost of a miss is one discovery per bump.
