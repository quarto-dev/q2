## Overview

Split `PandocWriteStage::run` into a pure `prepare()` that returns a `PandocRequest` and a native-only `execute()`, and give the request a transport out of the pipeline. Native behaviour is unchanged. Scope is **docx, single document, remote images left to pandoc (`Q-11-1` + alt text)**. Request paths are `/`-normalized absolute strings, never `PathBuf`, so Windows native requests contain no backslashes in `argv`, `env` or `files` paths (the base64 params blob keeps what its builders emit and is normalized only inside the comparison tests).

## Decisions

- An ungated `PandocPrepareStage` writes `RenderContext::pandoc_request` (a `PipelineData` variant is the rejected alternative: it touches `PipelineDataKind` and every match, `stage/data.rs:37,74`).
- From R0's exploration (`../research/2026-10-01-pandoc-hashable-request.md`, approved by Gordon at R0's STOP): the schema ships `schema_version` (integer; the host refuses an unknown one) and a Rust-computed `job_id` (opaque to TS: first 16 hex of sha256 over the canonical JSON, keys sorted, of `{schema_version, tool: wasm_sha256, argv[1..], env minus SOURCE_DATE_EPOCH, files: {path: sha256}, share_tree: share_tree_version}`), and reserves `kind` (default `pandoc`) so PDF can later be a second job fed by the first (R1 keeps `post` as is). `SOURCE_DATE_EPOCH` is in `env` (click time in production, fixed in tests). `prepare()` emits placeholder-rooted paths (`/__q2_tmp__`, `/__q2_doc__`, `/__q2_share__`, matching the recordings) so the `job_id` is stable across renders. Epub gets a document-derived `identifier` in R5 (random `urn:uuid:` otherwise); epub is compared semantically, not byte-wise.
- Contract details fixed when the schema was published (for review at the STOP): (a) `job_id` also hashes `resource_refs` (`{path: sha256}`), which the R0 prototype did not need because its recordings kept every input under `files`; without it two renders differing only in an image's bytes would share an id. (b) The request has an explicit `share_tree_path` (`<share_root>/pandoc-share`, equal to `QUARTO_SHARE_PATH`): the design puts the share tree there while the R0 recordings mount it at `/__q2_share__` itself, so the host must be told where to mount rather than guess. (c) `typst_available_fonts` is a required key (`null` until PDF). (d) Byte fields are base64 in JSON (`contentEncoding: base64`, `x-q2-wire: Uint8Array`); the schema is draft 2020-12 with `additionalProperties: false`, and the golden is checked by the `jsonschema` crate (dev-dependency).
- The request carries its own bytes; `resource_refs` holds paths and bytes copied by Rust in the same synchronous step (D3).

## Checklist

### Tests first
- [x] `job_id` is stable and sensitive: two `prepare()` calls on the same document give the same id (different temp roots and `SOURCE_DATE_EPOCH` included), and the id changes with one env var, one argv element or one file's bytes (R0's prototype: 24 distinct ids over the 24 recordings, each of those changes flips the id).
- [x] `prepare()` makes no filesystem write: point `share_root` and `doc_dir` at a nonexistent directory and assert it still does not exist afterwards (a mock runtime cannot intercept `std::fs`). Reads go through the runtime only (done as: `prepare()` succeeds with `share_root`, `doc_dir` and the project dir all nonexistent, which a direct `std::fs` read of a needed file would fail; a wrapper runtime cannot intercept `std::fs`, so no stronger check exists; the typst reads, e.g. `typst_highlight.rs`\'s, are converted in R4). `prepare()` also reads the process-global `set_cli_path` value: request-comparison tests set it or exclude `quarto-cli-path`.
- [x] Argv and env of the docx request are compared against the *recorded real native run* from R0's wrapper (after normalizing the temp root, `quarto-cli-path` and Typst path inside `QUARTO_FILTER_PARAMS`, Windows separators, and excluding `SOURCE_DATE_EPOCH`), not against `prepare()` itself; assert structural request fields rather than a golden of the whole wire JSON (any pampa AST change would break that).
- [x] Every path-valued argv entry starts with `/` (or `X:/` for a native Windows request) and has no `\`, including a document with a relative `highlight-style` (a value ending `.theme` or `.xml` resolves against `doc_dir` on native and wasm, an intended native fix with its own test, since it changes native argv and is not covered by "native behaviour unchanged"; other values pass verbatim); env keys are an allowlist (no `LANG`/`LC_*`); on a wasm-style `PrepareOptions` (`collect_resources`, `source_date_epoch: Some`) `dirs` contains `/tmp` and `request.share_root` equals the constants file's `share_root`, and a native-style one has neither `/tmp` nor `SOURCE_DATE_EPOCH`; a pure test runs `C:\proj\a.qmd`, `\\?\C:\proj\a.qmd`, `\\server\share\a.qmd` and a lowercase drive through the normalizer on every OS.
- [x] Mount rules (design: Contracts): identical entries within a list are deduped; `prepare()` fails on a path in two of `files`/`resource_refs`/`dirs`, on a path that is both file and directory, on a `files` path equal to a share-tree entry, and, in wasm mode only (native temp roots may sit under `/tmp`), on a `resource_refs` path under `/__q2_share__` or `/tmp` and a `files` path under `/tmp`.

  - [x] **STOP: human review after the split** (the riskiest refactor).
- [x] **Define `PandocRequest` fully.** Fields:
  - `writer`; `argv` (whole argv incl. argv[0] and RTS options); `env` (`QUARTO_SHARE_PATH`, `QUARTO_FILTER_PARAMS`, `QUARTO_FILTER_DEPENDENCY_FILE`, `SOURCE_DATE_EPOCH` (`PrepareOptions.source_date_epoch`, supplied by `render_pandoc_request`: click time in production, fixed in tests; `None` natively); env is fixed at init so TS gets it as data);
  - `files` (input JSON, which is the one copy of the wire AST, with `json_path` naming it; the empty deps file that must exist; template dir; staged user template/partials; **bytes included**);
  - `dirs` (the parent of `output_path`; `.quarto/`, which `pandoc_write.rs:~722` creates for every non-single-file project; and, in wasm mode, `/tmp`; directories that only parent a file are implicit, design: Contracts, mount rules; the mediabag and results-file parents are deliberately absent: native never creates them, and listing the mediabag directory would leave an empty `<stem>_files` next to every native output);

  - `share_root`/`doc_dir`/`project_root` (the allowed root of D3); `output_path`; `stage_name` and `json_path` (for classification); a typed `post` (none for these formats; `compile_typst` reserved); `expected_pandoc_wasm_sha256`; `share_tree_version` (defined here: SHA-256 over the sorted `(path, bytes)` entries of `FILTERS_DIR`, `DATADIR_DIR` and `FORMATS_DOCX_DIR` (the three trees native `extract_share_tree` writes), deduped; `include_dir` entry order is not a contract; R2's bundle reuses it); the fields R0's exploration recommends; and `typst_available_fonts: Option<…>` (echoes `render_pandoc_request`\'s input of the same name, R2; `None` until the PDF work).
