## Overview

Split `PandocWriteStage::run` into a pure `prepare()` that returns a `PandocRequest` and a native-only `execute()`, and give the request a transport out of the pipeline. Native behaviour is unchanged. Scope is **docx, single document, remote images left to pandoc (`Q-11-1` + alt text)**. Request paths are `/`-normalized absolute strings, never `PathBuf`, so Windows native requests contain no backslashes in `argv`, `env` or `files` paths (the base64 params blob keeps what its builders emit and is normalized only inside the comparison tests).

## Decisions

- An ungated `PandocPrepareStage` writes `RenderContext::pandoc_request` (a `PipelineData` variant is the rejected alternative: it touches `PipelineDataKind` and every match, `stage/data.rs:37,74`).
- From R0's exploration (`../research/2026-10-01-pandoc-hashable-request.md`, approved by Gordon at R0's STOP): the schema ships `schema_version` (integer; the host refuses an unknown one) and a Rust-computed `job_id` (opaque to TS: first 16 hex of sha256 over the canonical JSON, keys sorted, of `{schema_version, tool: wasm_sha256, argv[1..], env minus SOURCE_DATE_EPOCH, files: {path: sha256}, share_tree: share_tree_version}`), and reserves `kind` (default `pandoc`) so PDF can later be a second job fed by the first (R1 keeps `post` as is). `SOURCE_DATE_EPOCH` is in `env` (click time in production, fixed in tests). `prepare()` emits placeholder-rooted paths (`/__q2_tmp__`, `/__q2_doc__`, `/__q2_share__`, matching the recordings) so the `job_id` is stable across renders. Epub gets a document-derived `identifier` in R5 (random `urn:uuid:` otherwise); epub is compared semantically, not byte-wise.
- The request carries its own bytes; `resource_refs` holds paths and bytes copied by Rust in the same synchronous step (D3).

## Checklist

### Tests first
- [ ] `job_id` is stable and sensitive: two `prepare()` calls on the same document give the same id (different temp roots and `SOURCE_DATE_EPOCH` included), and the id changes with one env var, one argv element or one file's bytes (R0's prototype: 24 distinct ids over the 24 recordings, each of those changes flips the id).
- [ ] `prepare()` makes no filesystem write: point `share_root` and `doc_dir` at a nonexistent directory and assert it still does not exist afterwards (a mock runtime cannot intercept `std::fs`). Reads go through the runtime only (for docx, a wrapper-runtime test fails on any direct `std::fs` read; the typst reads, e.g. `typst_highlight.rs`'s, are converted in R4). `prepare()` also reads the process-global `set_cli_path` value: request-comparison tests set it or exclude `quarto-cli-path`.
- [ ] Argv and env of the docx request are compared against the *recorded real native run* from R0's wrapper (after normalizing the temp root, `quarto-cli-path` and Typst path inside `QUARTO_FILTER_PARAMS`, Windows separators, and excluding `SOURCE_DATE_EPOCH`), not against `prepare()` itself; assert structural request fields rather than a golden of the whole wire JSON (any pampa AST change would break that).
- [ ] Every path-valued argv entry starts with `/` (or `X:/` for a native Windows request) and has no `\`, including a document with a relative `highlight-style` (a value ending `.theme` or `.xml` resolves against `doc_dir` on native and wasm, an intended native fix with its own test, since it changes native argv and is not covered by "native behaviour unchanged"; other values pass verbatim); env keys are an allowlist (no `LANG`/`LC_*`); on a wasm-style `PrepareOptions` (`collect_resources`, `source_date_epoch: Some`) `dirs` contains `/tmp` and `request.share_root` equals the constants file's `share_root`, and a native-style one has neither `/tmp` nor `SOURCE_DATE_EPOCH`; a pure test runs `C:\proj\a.qmd`, `\\?\C:\proj\a.qmd`, `\\server\share\a.qmd` and a lowercase drive through the normalizer on every OS.
- [ ] Mount rules (design: Contracts): identical entries within a list are deduped; `prepare()` fails on a path in two of `files`/`resource_refs`/`dirs`, on a path that is both file and directory, on a `files` path equal to a share-tree entry, and, in wasm mode only (native temp roots may sit under `/tmp`), on a `resource_refs` path under `/__q2_share__` or `/tmp` and a `files` path under `/tmp`.

### Tasks
- [ ] **Path normalizer.** A pure `normalize_request_path(&Path) -> String` in `quarto-core` (drive-letter and `\` aware, handles verbatim `\\?\C:\` and UNC prefixes and drive-letter case, collapses `.`/`..`, `/`-separated; `ProjectContext::discover` canonicalizes, which yields verbatim paths on Windows). `prepare()` and R2's `resource_refs` use it; `VirtualFileSystem::normalize_path` (an instance method joining against `project_root`, `vfs.rs:319`) is not it.
- [ ] **Publish the contract first** (hand-authored, before any refactor): `crates/quarto-core/schemas/pandoc-request.schema.json`, a hand-written golden request for one fixture (`crates/quarto-core/schemas/pandoc-request.golden.json`), and `PandocRequest` as a bare serde struct with the field list below. Pin the bytes mapping (design: Contracts), the entry shape of `files`/`resource_refs` (`{path, bytes}`) and the `argv[0]`/RTS values (`pandoc`; no `+RTS` unless H0 finds one needed). Tests: the golden validates against the schema and round-trips through the Rust type. The golden is regenerated from a real `prepare()` at the end of this phase.
- [ ] **STOP: human review of the schema** (the person starting H1; H1 may start after it and after H0). Hand back after updating the Handoff log.
- [ ] **Request transport.** `run_pipeline` (`pipeline.rs:883`) builds a `StageContext` and drops it in `finish_pipeline_result`; `restore_render_context` (`:1112`) copies back only an explicit field list (the pattern is `citation_manifest`, `:1154`). So: an **ungated** `PandocPrepareStage` (`#[async_trait(?Send)]`; testable natively; `wasm.md` forbids `cfg(any(wasm32, test))`) writes `RenderContext::pandoc_request`, bridged in `stage_context_from_render_context` / `restore_render_context`; its output kind in the kind chain is an empty `RenderedOutput`. `prepare()` takes an explicit `PrepareOptions { temp_root, source_date_epoch: Option<i64>, collect_resources: bool }` (on wasm the constant `/__q2_share__`, via a hook in `stage_context_from_render_context` (`:1000`) that calls `StageContext::with_temp_dir`, `context.rs:494`; a native test passes the same value). `PrepareOptions` rides in as an input-only `RenderContext` field bridged one way like `defer_citeproc` (`pipeline.rs:~1069`); on wasm every stage's `ctx.temp_dir()` then returns the share root. `with_temp_dir` seeds a lazy cell that `set` cannot overwrite, so the hook must run before anything calls `temp_dir()`, and `temp_root` must be fixed before `prepare()` because absolute temp paths are baked into `QUARTO_FILTER_PARAMS`. Test: the stage carries a stub request through the bridge (the real `prepare()` lands in the split task).
- [ ] **Split `PandocWriteStage::run`** (`run` is ~570 lines) into pure `prepare()` and native `execute()`, as three checkboxes, each ending with T10.x and goldens green:
  - [ ] **Effect list** replacing the ~10 interleaved `std::fs` sites (json write `:759`, share extract `:769`, output mkdir `:840`, deps file `:856`, `.quarto` mkdir `:722`, epub formats `:159`; the typst-only sites (template dir `:784-811`, partials `:1138`, `typst_template_path` staging, the `--defaults` toc yaml `:893`, packages `:373`, the highlight-definitions read) stay native-gated direct `std::fs` calls inside `prepare()` until R4 converts them; typst brand-font staging (`stage_typst_brand_fonts`, `:329`, which fetches and writes into the project) and `typst fonts` discovery (`resolve_typst_available_fonts`, ~`:364-406`) are not effects: their result feeds the params blob, so they stay a native pre-step whose outputs `prepare()` takes as one input struct: `typst_available_fonts: Option<Vec<String>>` (the same input `render_pandoc_request` supplies on wasm) and the other values that pre-step computes (`brand`, `logo`, `brand_mode`, `citation_location`, `reference_location`, `cite_method`), plus `shift_heading_level_by`. `prepare()` takes `&StageContext`, so it reports diagnostics in its result. The effect list is a set of final contents, not an ordered script: the user template overlay on the vendored `template.typ` and the partials copied into the same directory (`:784-821`) are resolved inside `prepare()` into each file's bytes, and the share tree is derived from `temp_root` rather than listed in `files`, because the callout icon paths in `QUARTO_FILTER_PARAMS` point into it. The argv builders (`build_forwarded_args`, `epub_extra_args`) emit both `--flag value` pairs and `--flag=<path>` single tokens, so they return typed path arguments that `prepare()` normalizes; a non-UTF-8 path is a `prepare()` error).
  - [ ] **Native executor**, behaviour unchanged. The version gate and `retain_temp_json_unless_success` stay native-only in `execute()`; `unescape_shortcodes_in_output` (`:1175`) is a markdown-family post-step, out of scope here (`post` is `none` for the four formats). Native mode is `collect_resources: false`: `resource_refs` are recorded as paths only (the files already exist at those paths), `dirs` omit `/tmp`, and there is no `SOURCE_DATE_EPOCH`; `execute()` extracts the share tree under `share_root` (it is not part of `files`), writes `files`, creates `dirs`, applies `env` over the inherited environment, and replaces argv[0] with the resolved binary. **Open (Windows native, manual-only):** whether the vendored `init.lua` absolute-path check accepts `C:/x` argv and `-L` values, or `execute()` converts back to native separators. `classify_pandoc_completion` moves out of the gated file, keeping its public re-export path (`stages/mod.rs:~136`, `tests/integration/pandoc_transport.rs:26`).
  - [ ] **Behavioural test** (in `tests/integration/`, registered in `main.rs`) replacing the source-grepping test at `pandoc_write.rs:1446-1466` (it asserts two strings, including `resolve_and_gate_pandoc(self.name(), ctx.runtime.as_ref())?`).
  - [ ] **STOP: human review after the split** (the riskiest refactor).
- [ ] **Define `PandocRequest` fully.** Fields:
  - `writer`; `argv` (whole argv incl. argv[0] and RTS options); `env` (`QUARTO_SHARE_PATH`, `QUARTO_FILTER_PARAMS`, `QUARTO_FILTER_DEPENDENCY_FILE`, `SOURCE_DATE_EPOCH` (`PrepareOptions.source_date_epoch`, supplied by `render_pandoc_request`: click time in production, fixed in tests; `None` natively); env is fixed at init so TS gets it as data);
  - `files` (input JSON, which is the one copy of the wire AST, with `json_path` naming it; the empty deps file that must exist; template dir; staged user template/partials; **bytes included**);
  - `dirs` (the parent of `output_path`; `.quarto/`, which `pandoc_write.rs:~722` creates for every non-single-file project; and, in wasm mode, `/tmp`; directories that only parent a file are implicit, design: Contracts, mount rules; the mediabag and results-file parents are deliberately absent: native never creates them, and listing the mediabag directory would leave an empty `<stem>_files` next to every native output);
  - `resource_refs` (**paths and bytes**; TS never reads the VFS), defined here and left empty; R2 computes it;
  - `share_root`/`doc_dir`/`project_root` (the allowed root of D3); `output_path`; `stage_name` and `json_path` (for classification); a typed `post` (none for these formats; `compile_typst` reserved); `expected_pandoc_wasm_sha256`; `share_tree_version` (defined here: SHA-256 over the sorted `(path, bytes)` entries of `FILTERS_DIR`, `DATADIR_DIR` and `FORMATS_DOCX_DIR` (the three trees native `extract_share_tree` writes), deduped; `include_dir` entry order is not a contract; R2's bundle reuses it); the fields R0's exploration recommends; and `typst_available_fonts: Option<…>` (echoes `render_pandoc_request`'s input of the same name, R2; `None` until the PDF work).
