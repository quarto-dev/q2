## Overview

Implements [`../designs/preview-vfs-contract.md`](../designs/preview-vfs-contract.md).
Evidence and costings: [`../research/2026-11-07-preview-vfs-options.md`](../research/2026-11-07-preview-vfs-options.md).

The end state: the render runs in a Web Worker; whenever the VFS cannot
answer a read, an existence check or a directory listing, the worker asks
the preview server over a synchronous XHR, the server applies one exposure
policy and answers from disk, pulled files are promoted into Automerge, and
the server watches what it has served. Nothing is pushed that a render did
not ask for. The render reports what it read, and that read set decides
which edits re-render the page. The single-file dependency extractors and
the `/api/preview/deps` predictor go away.

Each phase is a separate worktree and PR off `main` (or off the previous
phase's branch when it depends on it). Tests come first in every phase.
Phases 0 and 1 are pure Rust; Phase 2a moves the preview SPA's render into
a worker with no change in behaviour; Phase 2b adds the miss path on top;
Phase 3 measures and removes the predictors; Phase 5 is docs. Phase 4
(hub-client on the worker) is no longer part of this epic; see its section.

Phase 2 was one phase until the 2026-11-10 review. It is split because the
worker move is a large refactor that can be verified on its own by parity,
and the miss path is small once the worker exists. Landing them together
would have put every user-visible fix behind the whole of both.

Measure before optimising. The loopback cost of a round trip is 0.3 ms and
a remote link costs its RTT per sequential trip (contract D2). Any batching
or prefetch is added only when the Phase 2b and 3 measurements, local and
with injected latency, show a cold render needs it.

Out of scope here: the `preview-scss-theme` branch itself. Its project-mode
change (sync `.css`/`.scss` found by the walk) ships on its own; its
single-file theme heuristic is already removed. Phase 0 branches off `main`
without waiting for it (decided 2026-11-10); whichever lands second rebases
onto the other, and the theme branch then adopts the policy module in place
of its own provenance check in `discovery.rs`.

## Phase 0: exposure policy

One module, `crates/quarto-hub/src/exposure.rs`, implementing contract D4.
Discovery, the watch filter and the preview's single-file resolver call it;
their private ignore lists and `in_generated_dir` go away.

Tests first (`crates/quarto-hub/src/exposure.rs` unit tests):

- [x] Lexical containment: `..` above the root, absolute paths, and a
  `/project/` prefix are handled; `a/../b` inside the root is admitted.
- [x] Canonical containment: a symlink inside the root that points outside
  is refused; a symlink that points inside is admitted (unix-only helper
  pair per `.claude/rules/cross-platform.md`).
- [x] Hidden components below the root are refused; a root under a hidden
  directory is fine.
- [x] Generated by provenance: `index_files/x.css` is refused when
  `index.qmd` exists beside it and admitted when it does not;
  `static_files/brand.scss` with no `static.qmd` is admitted; `site_libs`
  at any depth is refused; the project's `output-dir` is refused.
- [x] Extension allow-list per class, including `.sass`; `.env` and unknown
  extensions refused.
- [x] Size cap refuses with a typed reason, not a panic; the cap is the
  per-file limit in `resources/pandoc-wasm.json`.
- [x] Discovery produces the same `ProjectFiles` as before for the existing
  fixtures (regression over `discovery.rs` tests), minus the generated-dir
  differences above.

Implementation:

- [x] `exposure.rs`: `ExposurePolicy { root, canonical_root, output_dir }`
  with `admit(&self, rel: &Path, class: Class) -> Result<Admitted, Refusal>`
  and `classify(ext) -> Option<Class>`.
- [x] `ProjectFiles::discover` uses the policy for ignore and generated
  decisions; `GENERATED_DIRS`, `GENERATED_DIR_SUFFIXES`, `is_ignored` and
  `in_generated_dir` are removed from `discovery.rs`.
- [x] `WatchFilter::PreviewBroad` and `static_mode/watch_policy.rs` use the
  policy for the generated-dir decision.
- [x] `output-dir` is read from the project config and passed to the policy.
- [x] Canonical containment is correct on Windows: `\\?\` verbatim prefixes
  and case-insensitive roots compare equal to the canonical root (follow
  whatever the repo already does for canonicalize comparisons).
- [x] `cargo clippy -p quarto-hub -p quarto-preview -p quarto --all-targets -- -D warnings`
  on the host.
- [ ] The same with `--target x86_64-pc-windows-msvc`: does not cross-check

### Phase 0 record (2026-11-10)

Deviations from the sketch above, and why:

- `admit` takes no `Class` argument and `classify` takes the path, not an
  extension. The class depends on the name (`_quarto*.yml`) and on an
  `_extensions/` ancestor, and a caller-supplied class could disagree
  with the file. The API is `admit` (checks 1 to 5, for eager sync),
  `admit_pull` (plus the size cap, for the Phase 1 routes), `admit_dir`
  (for list and exists), `admit_lexically` / `admit_dir_lexically` (no
  canonicalization, for the walk), and `event_in_generated_dir` (for the
  watcher, which holds absolute event paths).
- On `main` the names the plan says to remove from `discovery.rs`
  (`GENERATED_DIRS`, `GENERATED_DIR_SUFFIXES`, `in_generated_dir`) live
  only on `preview-scss-theme`; on `main` they were in
  `static_mode/watch_policy.rs`, and are removed from there. `is_ignored`
  is removed from `discovery.rs`.
- The owned-directory list keeps the walk's old ignores so discovery does
  not widen: `node_modules`, `__pycache__`, `_freeze`, `site_libs`, plus
  `_site`, `_book` (default output directories, for `quarto hub`, which
  does not parse `_quarto.yml`), `renv`, `venv`, `target`.
- `_extensions/` is admitted wholesale (class `Extension`) except key
  material (`.pem`, `.key`, ...), because discovery has always synced
  every text file in it.
- The size cap applies to pulls only. Eager sync keeps no cap, so the
  walk does not drop a large video it synced before.
- `output-dir` reaches the hub as `HubConfig::output_dir`, resolved by
  `quarto_preview::config::resolve_project_output_dir`; `quarto hub`
  passes `None`.
- The single-file resolver now admits its includes, images, `resources:`
  matches and `render-components:` through the policy.
- Windows: canonical comparisons go through
  `quarto_system_runtime::canonicalize` (`dunce`), as elsewhere.

Behaviour changes in discovery, beyond the generated-directory ones:
hidden *files* are no longer synced (only hidden directories were
skipped), and a symlink that resolves outside the root is no longer
synced.

End-to-end check: `q2 preview <fixture> --no-browser --port 47811` on a
website with `output-dir: public`, then `curl /api/documents`. The
fixture held `index.qmd`, `img/ok.png`, `static_files/logo.png`,
`index_files/figure-html/plot.png`, `public/out.png`,
`deep/site_libs/icon.svg`, `.draft.qmd`, and `leak.md` symlinked to
`/etc/hosts`. The index held exactly `_quarto.yml`, `index.qmd`,
`img/ok.png` and `static_files/logo.png`. Output inspected.

## Phase 1: miss route, promotion, demand-driven watch

Server side only. Contract D2, D6, D7, D8.

Decide first:

- [x] The request gate (contract D6). The preview server validates neither
  `Host` nor a token, so a DNS-rebinding page is same-origin with it and
  can already read the project over `/ws`. The miss routes widen that, in
  single-file mode, to every admitted file under the deck directory.
  Choose between a router-wide `Host` allow-list (loopback names plus the
  `--host` value, with an escape for a reverse proxy such as Posit
  Workbench) and a per-session token in the URL the CLI opens (works
  through proxies, changes the preview URL and the join string). This is
  the user\'s call; record it in the contract. The routes below ship behind
  it, and the gate covers the whole router, not only the new routes.

Tests first:

- [x] The gate: a request whose `Host` (or token) fails the chosen rule is
  refused on `/api/*`, `/health` and the `/ws` upgrade; a `--join` guest
  through the tunnel and a request through a configured proxy pass.

- [x] `crates/quarto-preview/tests/integration/`: `GET /api/preview/file?path=`
  returns bytes for an admitted path, 404 for an absent one, 403 with a
  reason for a refused path (traversal, symlink escape, hidden, generated,
  extension, size), and never follows a path outside the root (the route
  test reuses the Phase 0 fixtures).
- [x] `GET /api/preview/stat?path=` answers exists/is-file/is-dir for
  admitted paths and 403 for refused ones; a refused path is
  indistinguishable from an absent one to the caller only in that both
  are "no" (the 403 reason is for diagnostics).
- [x] `GET /api/preview/list?path=` returns only names the policy admits;
  a listing of a refused or absent directory is 403 or 404, never partial.
- [x] After a successful file pull the path is in the Automerge index and a
  disk edit to it is synced (promotion plus watch).
- [x] After a stat or list answer for a directory, a file created in it that
  the policy admits appears in the index and bumps the VFS generation;
  a file created in a directory nothing asked about does not.
- [x] Project mode: a file created after boot that the policy admits appears
  in the index without restart (the existing gap).
- [x] Single-file mode: nothing outside the deck and its declared config is
  synced, listed or watched until a route asks for it.

Implementation:

- [x] The gate chosen above, as one layer over the router.
- [x] `HubContext::import_path(rel)`: one iteration of
  `reconcile_files_with_index` factored out, idempotent, records a
  checkpoint under the `sync_state` mutex.
- [x] Routes `file`, `stat`, `list` under `/api/preview/` in
  `extend_with_preview`, each calling the policy first; `file` then calls
  `import_path` and returns the bytes.
- [x] Watch set: a directory the server has answered for is added to the
  watcher; create events in watched directories go through the policy and
  `import_path`; the frozen allow-list in `FileWatcher::new` is removed.
  Project mode keeps its tree watch and gains enrolment.
- [x] Enrolment syncs the new file whole; its arrival bumps the browser
  VFS's generation, which is the negative-cache key. No server-side
  counter. Confirm single-file mode's sync path adds to the same index.
- [x] `.bib` and `.csl` (and the other classes in the policy's allow-list
  that the walk does not classify today) are admitted by the three routes
  in both modes; a route test pulls a `.bib` in project mode and in
  single-file mode.
- [ ] Quarto 1 check: when a quarto-cli checkout is available, compare its
  preview watch rules (input plus the render's reported resource files) and
  note any case ours misses here.
- [x] `--join` guests: confirm the routes tunnel like other `/api/*`
  routes (they should; add a tunnel test if the existing ones do not cover
  a new route).

### Phase 1 record (2026-11-10)

- Gate: the `Host` allow-list (contract D6 records the rule). The proxy
  escape is the `QUARTO_PREVIEW_ALLOWED_HOSTS` environment variable rather
  than a CLI flag, so it reaches `q2 preview` through Workbench-style
  launchers without new plumbing; Phase 5 documents it.
- Wire shapes. `file` answers the bytes as `application/octet-stream`.
  `stat` answers `{exists, isFile, isDir}`, with `exists: false` (200) for
  an absent path that passes the lexical checks. `list` answers
  `{entries: [{name, kind}]}`, `kind` being `file` or `dir`, sorted by
  name. Refusals are 403 with the reason as text; an absent file or
  directory (and a `list` of a file) is 404.
- `stat` of a missing path watches its parent directory, so the file is
  enrolled when it appears (the Sass-probe case).
- Enrolment is creation-only in single-file mode: a watched directory
  records the names it held when first watched, and only a name not among
  them is enrolled. Otherwise editing an untouched sibling in a probed
  directory would sync its contents, which contract D5 forbids. Project
  mode enrols what the boot walk would have synced
  (`ProjectFiles::walk_syncs`), so a new file arrives as if the preview had
  restarted.
- `WatchFilter::PreviewBroad` is now the policy's class list
  (`exposure::classify`), and the watcher drops events the policy refuses
  lexically (hidden, generated, unknown type). Without this, edits to a
  pulled `.bib` or `.scss` would never surface.
- The size cap applies to pulls (`file`, and single-file enrolment), not to
  project mode's eager walk.
- `join_frontend` test helpers sent `Host: join-frontend-test`; they now
  send `localhost`, which is what a guest's browser sends. A new test
  pulls through the tunnel and checks that the gate refuses a foreign
  `Host` that arrives through it.
- Quarto 1 check not done: no quarto-cli checkout is in the tree.

End-to-end check: `q2 preview <dir>/deck.qmd --no-browser --port 47823`
on a deck citing `refs.bib`, beside `notes.qmd`, `.env` and empty
`partials/` and `other/`. Observed, with output inspected: the index at
boot is `["deck.qmd"]`; `file?path=refs.bib` returns the bibliography
(200) and the index becomes `["deck.qmd","refs.bib"]`; `.env` returns 403
"hidden paths are not served"; `../x.qmd` returns 403 "the path climbs
above the project root"; `stat?path=partials/_v.scss` returns
`{"exists":false,...}`. After creating `partials/_v.scss` and
`other/o.scss`, the index is `["deck.qmd","partials/_v.scss","refs.bib"]`.
`curl -H 'Host: evil.example' /health` returns 403, and
`http://localhost:<port>/health` returns 200.

### Phase 2a record (2026-11-10)

Shape, and where it differs from the sketch above:

- The facade is not a second module. `wasmRenderer.ts` gained a pluggable
  `EngineBackend` (`installEngineBackend`). The SPA installs the worker
  backend (`startWorkerEngine` in
  `ts-packages/preview-runtime/src/worker/engineClient.ts`, imported by
  subpath so hub-client never bundles the worker); hub-client installs
  none. With the backend installed, `initWasm` starts the worker, the VFS
  exports read a main-thread mirror (`worker/vfsMirror.ts`) and forward
  writes in order, and `renderPageForPreview` renders in the worker. The
  synchronous engine helpers throw there; `...Async` forms
  (`resolvePandocFormatsAsync`, `parseQmdContentAsync`,
  `applyNodeEditAsync`, `regenerateNestedBuffersAsync`) answer in either
  mode. `automergeSync.ts` and `preview-renderer` are unchanged.
- "Render responses carry the resources main-thread readers need" is done
  by the mirror. It holds every synced file (so the asset manifest, the
  PDF pane and the post-processor read sources as before), and each
  `renderPreview` answer carries the `/.quarto/` artifacts the render
  changed (the theme CSS). The worker diffs artifacts against what it
  last sent; the diff costs under 1 ms.
- Ordering (contract D9): the worker's RPC is serial, so a write that
  arrives during a render waits for it. The main thread keeps the
  coalescing render queue, so at most one render is in flight.
- `renderedSource` (the first commit of this phase) replaced the SPA's
  pre-render VFS snapshot, which a queued or worker render could outlive.
- `isTypstPdf` is asynchronous. The page kind is recorded per path, and
  the render effect waits until the active page has one, so a PDF page
  never flashes the HTML overlay. `regenerateNestedBuffers` runs from an
  effect after the render rather than inside the render response; same
  result, one less coupling.
- Not needed by the SPA, so not built: prefetching the fixed tables
  (formats, import table, project choices, share tree, typst versions)
  and proxying `renderPandocRequest` abort and progress. The SPA calls
  none of them; downloads and PDFs go through server routes. They belong
  to hub-client's move (Phase 4).
- Worker build: `worker.format: 'es'` in the SPA's Vite config only (the
  engine's dynamic imports need code-splitting). hub-client's global
  IIFE worker config is untouched. The embed's exactly-one hashed `.wasm`
  check holds; `cargo xtask build-q2-preview-spa` and
  `cargo build --bin q2` verified.
- Opaque-origin sandbox (`sandbox="allow-scripts"`): Chromium refuses a
  module worker from the page's `blob:` URL and a worker from the
  server's URL. The SPA starts a classic blob worker that loads the real
  one with a dynamic `import()` and replays messages that arrived first.
  `sandboxed-frame-theme.spec.ts` caught this.
- hub-client's copy of `perfCounters.ts` is kept byte-identical (a test
  enforces it). That sync is its only change; it is not user-facing, so
  no changelog entry.

Parity, Chromium, on a 60-section themed document (navigation to first
render; force-refresh to the next render, median of 12; three runs
each, all within a few ms of each other):

| Build | Cold | Warm median |
|---|---|---|
| Main thread (worker off) | 1010 ms | 33 ms |
| Worker | 1040 ms | 47 ms |

Inside the worker the render takes 12 to 13 ms and the artifact diff
under 1 ms. The added warm time is the boundary: the response (a 226 KB
AST) is cloned across, and a refresh also asks for the page kind. The
page's main thread no longer runs the render. Revisit if Phase 2b or 3
measurements show the clone matters.

E2E: the Chromium project passes as before (60 passed, 6 skipped; the 7
`typst-pdf-preview.spec.ts` failures are the local pandoc 3.12.1 against
the required 3.13, identical on the main-thread build). New specs:
`render-queue.spec.ts`, `render-worker.spec.ts` (the worker exists, the
page never fetches the engine `.wasm`, and the theme compiled in the
worker reaches the iframe). The Firefox project could not run locally:
Playwright's Firefox fails to launch on this machine ("Could not find
profile folder") with or without the worker, so CI is the check there.
Output was inspected through those specs' assertions on the rendered
iframe DOM.

## Phase 2b: the miss path and the read set (preview SPA)

Contract D2, D7, D11. Depends on Phases 1 and 2a.

Tests first:

- [x] Rust: `WasmRuntime` miss hook unit test with a stub shim: a read miss
  calls the shim once, inserts, and a second read does not call it; a
  negative exists answer is cached and not re-asked until the generation
  changes; the lock is not held across the call (test with a re-entrant
  stub).
- [x] Rust, `vfs.rs`: a pull insert of a new path does not move the
  generation; a sync write of identical bytes to an existing path does not
  move it, for text and for binary; a sync write of different bytes, a
  create and a remove still do.
- [x] Rust: a directory that holds some files but has not been listed
  answers `dir_list` through the list arm, once; after that the listing is
  local until the generation changes.
- [x] Rust: the read set of a render holds the paths read, the paths
  probed (hits and misses) and the directories listed, scoped to that
  render; a render answered from the project cache still reports the
  project config among its reads.
- [x] TS: the echo of a promoted file (the same bytes arriving through
  `onFileAdded` or `onBinaryChanged`) does not bump `contentTick`.
- [x] Playwright, single-file deck: `theme: styles/deck.scss` importing
  `partials/_vars.scss` (a subdirectory) renders with the variable applied;
  adding a new `@import` to `_vars.scss` that pulls in a file created
  mid-session re-themes the page without restart.
- [x] Playwright, both modes: a `.bib` beside the document resolves
  citations on first render with no `resources:` entry.
- [x] Playwright, one cold render: the render count is one. The pulls of
  that render and their echoes do not start a second render, and a forced
  second render makes no request to the miss routes (`perf.vfs-pull`
  stays flat).
- [x] Playwright, read-set filter: editing a file in the read set
  re-renders; editing an unrelated sibling does not; creating a file at a
  path the render probed and missed does.
- [x] Playwright, latency: the same deck behind a delay proxy at 0, 20, 50
  and 100 ms (the proxy used for the 2026-11-10 measurement is a 20-line
  Node script; check it in under the e2e helpers). Record cold-render wall
  time and the `perf.vfs-pull` counts per arm and status. These numbers,
  not a guess, decide whether any batching is built.

Implementation:

- [x] `WasmRuntime` miss hook: sync externs for the three arms
  (`vfs_miss_read(path) -> Option<Uint8Array>`, `vfs_miss_stat(path)`,
  `vfs_miss_list(path)`) with `catch`, an eligible-prefix check (not
  `/__quarto_resources__`, not `/.quarto/`, not `/tmp/`), a negative cache
  keyed by the VFS generation; the read guard is dropped before the call
  and the write lock taken after.
- [x] Generation rules (contract D2): the hook inserts through a
  generation-neutral path; `vfs_add_file` and `vfs_add_binary_file` go
  through `add_file_if_changed` (it exists; only `file_write` and the
  artifact flush use it today) and report whether anything changed, and
  `automergeSync.ts` skips `onFileContent` / `onBinaryContent` when
  nothing did.
- [x] A per-directory "listed completely" bit in the VFS, set by the list
  arm, cleared with the generation.
- [x] JS shim: synchronous `XMLHttpRequest` with `responseType =
  'arraybuffer'` to the three routes; null on 404 or 403; a
  `perf.vfs-pull` gauge counting calls per arm and status, dumped with the
  other perf counters.
- [x] `vfsIsFile` goes through the exists arm with the same negative cache,
  so a Sass probe is asked once per generation.
- [x] Read set (contract D11): `WasmRuntime` records reads, probes and
  listings in a per-render scope; the project cache stores the reads made
  while an entry was built and a cache hit adds them; the render response
  carries the set.
- [x] `PreviewApp.tsx`: `shouldRerenderForTextChange` and the binary
  handler filter on the read set (previous set kept after a failed render;
  no set yet means pass everything). The `/api/preview/deps` fetch stays
  until Phase 3 removes the endpoint.
- [x] End-to-end check recorded here: the exact `q2 preview` invocation, the
  observed re-theme, and a note that the output was inspected.
- [x] Decision recorded here from the latency run: no batching, or which
  prefetch (directory names on a probe, stylesheet closure on a pull) and
  why, with the before/after counts.

### Phase 2b record (2026-11-10)

Shape:

- The miss logic is target-independent, in
  `crates/quarto-system-runtime/src/demand.rs` (`Demand`), unit-tested
  natively with a stub handler; `WasmRuntime` delegates `file_read`,
  `path_exists`, `path_metadata` and `dir_list` to it. The JS side is not
  a `raw_module` extern but a handler object the worker installs with
  `vfs_set_miss_handler` (`read`, `stat`, `list`, each a synchronous XHR;
  `ts-packages/preview-runtime/src/worker/missShim.ts`). A throw answers
  "absent". hub-client installs none.
- Generation rules: `VirtualFileSystem::insert_pulled` never moves the
  generation; `vfs_add_file` / `vfs_add_binary_file` go through
  `add_file_if_changed` and answer `{ success, changed }`; the page's
  mirror answers the same; `automergeSync.ts` skips `onFileContent` /
  `onBinaryContent` when nothing changed. `/tmp` (render scratch) joined
  the generation-free prefixes, so a render's temp directories no longer
  flush the caches mid-render.
- Pulled files ride back in the render answer into the page's mirror, so
  the asset manifest sees them and their sync echo is an identical write.
- The read set is recorded from the start of `render_page_for_preview`
  and taken with `vfs_take_read_set`; `renderPageForPreview` returns it
  as `readSet`. The project cache rule (a cache hit reports the reads
  recorded when its entry was built) has no case today: render discovers
  its project directly; only format resolution uses `cached_project`.
  `Demand::record` is there for it.
- Re-render filter (`shouldRerenderForTextChange`): with the active
  page's read set, a text change re-renders when the path was read or
  probed, or when the file is *new* in a directory the render listed.
  Edits of existing files in a listed directory do not count: a listing
  depends only on names, and project discovery lists every directory, so
  counting them made the filter pass everything in project mode. `.tsx`
  always passes (the main thread compiles it). Binary edits still always
  re-render: in the preview AST, images are loaded on the main thread by
  the asset walker, not read by the render, so they never enter the read
  set. The `/api/preview/deps` filter remains the fallback until a set
  exists; Phase 3 removes it.

Measured, and the decision it made: a cold single-file render of a deck
with a custom theme made 766 `stat` round trips. dart-sass tries about
fourteen candidate names per `@import`, and Bootstrap's own imports are
tried against the theme's directory first. That is 0.2 s on loopback and
tens of seconds at 50 ms RTT. So the prediction rule is built: a probe
miss asks for its parent directory's listing once per generation, the
other candidates there are answered locally, and an absent directory
answers everything beneath it. The same render now makes 5 round trips
(3 listings, 2 reads). No other batching.

Latency (`e2e/demand-vfs-latency.spec.ts`, run with

by half the RTT each way). Single-file deck with a custom theme, two

| 50 ms | 2080 to 2130 ms | 3 list, 4 read |

The seven sequential pulls account for at most 0.7 s at 100 ms; the rest

## Details

### Measured round-trip cost

From the 2026-11-10 run (tables in the research note): 0.3 ms per
synchronous XHR from a worker on loopback, independent of payload up to
100 KB; behind a delay proxy the cost is the configured RTT plus about
4 ms. A thousand round trips cost 0.3 s locally and 100 s at 100 ms RTT.
The mechanism is therefore built plain, and the remote case is handled by
measuring the sequential chain length of real decks before deciding on
prefetch.

### The echo, and why the generation rules exist

Found in the 2026-11-10 review and checked against the code. A pulled file
is promoted, so the same bytes come back over sync a moment later. As the
code stands, that echo calls plain `add_file`, which moves the generation
for any file that is not a `.qmd`, `.md` or `.ipynb`, and it reaches
`onFileContent`, whose filter passes every non-source path. The result
would be a second full render after every cold render, and that render
would ask every negative probe again because the echo flushed them. On
loopback that is wasted work; at 50 ms it doubles the probe chain the
negative cache is there to remove. The pull insert itself has the same
effect inside a render, since creating a path also moves the generation.
Hence the two rules in contract D2 and the "render count is one" test in
Phase 2b.

### Why the policy comes first

Everything else (walk, the three route arms, watcher, `--share`) is only as
safe as the predicate they share. Phase 0 is small and lands alone so that
the `preview-scss-theme` branch can adopt the provenance rule immediately.

### Lock discipline in the miss hook

`std::sync::RwLock` on wasm32 without atomics aborts on contention rather
than waiting. The hook reads under the lock, drops the guard, calls the
shim, then takes the write lock to insert. The negative cache is a
`RefCell<HashMap>` outside the VFS lock, keyed by generation.

### Worker bundle shape

`hub-client/vite.config.ts` sets a global IIFE worker format with
`inlineDynamicImports` (for typst). A render worker under that config
inlines the lazy `import('sass')` and web-tree-sitter into its bundle,
which is acceptable off the main thread but changes the lazy-sass
property. Switching to `format: 'es'` is global and means re-testing the
typst and pandoc workers. Decide in Phase 2a with a size measurement.
