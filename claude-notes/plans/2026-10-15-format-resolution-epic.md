## Why this epic exists

Several places decide a document's format before, or without, consulting the project: `render_once` (`q2 render`), `q2 preview --static` (which also takes no `-M` or `--profile`, as the live viewer does not either), the wasm `detect_format_from_content` and hub-client's `classifyPreviewMode`. In a book whose `_quarto.yml` says `format: typst`, each of them sees `html`, so the book is rendered per chapter without book metadata (`Q-21-3`), the PDF pane never appears, and `--static` shows "site has no index.html". One early resolution was never shared with `MetadataMergeStage`, which merges the same layers late and differently.

The same survey found that book scope (E11 of the parity epic) is passed to the renderers through special options at every boundary: `--book-scope`, `Option<BookScope>` through `ProjectPipeline` and `PandocRequestInput`, `ScopeParam` on the native routes, a wasm request option, and scope arguments through the hub-client download code. Review then showed the deeper problem: E11 made `--to` and "a file was named" change the scope, which is why the format and the scope had to be decided together. This epic makes `book-scope` ordinary metadata, supplied per render by a runtime overlay when a user asks for something explicit, and derives the *default* scope from what is being rendered (the target). That removes every special path, makes the value readable by Lua and other filters, and makes the sequence project format, then scope, then final format a straight line.

## Terms

- **Target:** what the user asked to render. It is the existing `RenderMode` in `quarto-core` (`project/orchestrator.rs`): `Full` (whole project), `Subset(files)` (named files), `ActivePage(path)` (one page; preview). The CLI's own `RenderTarget` (`quarto/src/commands/render.rs`: `SingleDoc`, `FullProject`, `Subset`) is the argument classification that is mapped onto it; no new type is introduced. For the format and scope rules, `Subset` of one file and `ActivePage` are the same case ("one active document"); the orchestrator keeps its different dependency handling for them (`ActivePage` skips graph augmentation).
- **Requested scope:** the explicit `book-scope` value if a layer supplies one (FR5), else the target's default (FR3).
- **Consolidating format:** a format that builds one output for the whole book (`format_consolidates_book`: typst, epub).
- **Requested format:** `--to`, else a scalar `format` in the runtime layer (FR2).
- **Member / non-member:** a file is a *member* of a book when it is in the book's chapter list; a *non-member* is a file inside the project (in the render list) that is not a chapter. A file outside the project is neither.
- **Pseudo-format:** an internal format name from `builtin_pseudo_format` (`format.rs:~448-477`). Five exist: `q2-preview`, `q2-slides` (the revealjs preview) and `q2-sandboxed-preview` select the browser-preview pipeline; `q2-debug` and `q2-html-render` are plain html renders. All five are accepted as `--to` values today and stay so; this epic changes nothing about them (what they should mean on the command line is the open question `bd-pseudo-format-to-meaning-vxhyni3t`, FR19).

## Decisions

- **FR1 Format selection follows Quarto 1's key-list rule** (research §4; Q1 `resolveFormats`, `render-contexts.ts:425-443`), not prefer-merge of `format:` strings. Keys come from `format:` as a scalar or a map's keys; entries whose value is `null` or `false` are skipped. The *list*: the document's keys followed by the `_metadata.yml` chain's keys (Q1 treats directory keys as input keys); if that pool is non-empty it replaces the project's list, otherwise the project's list is used (the project layer already includes profiles, `_quarto-<name>.yml` and `_quarto.yml.local`, merged in `ProjectContext::parse_config`). The `_metadata.yml` chain is merged into one map first (a deeper file overrides a shallower one, a scalar replaces a map; Q1 `render-contexts.ts:411-420`, `directoryMetadataForInputFile` in `project-shared.ts`) and only then are its format keys taken (`config/metadata.ts:140-151`); keys of different layers are not unioned. Settings are merged separately and as today: project < `_metadata.yml` < document < runtime. The *selected* key is the requested format (FR2) if there is one, else the first key of the list; if no layer declares a key, `html` (as in Q1). The resolver returns the whole list, so Q-20-8 can say what was skipped. A requested format may name a format no layer declared.
- **FR2 Requested format.** `--to` wins over everything. Next comes a **scalar** `format` in the runtime layer (`-M format:typst`, or a request's `metadata`). This deliberately differs from Quarto 1, where `-M format:x` is not a quarto metadata key (`flags.ts:311-318`), reaches pandoc as a plain variable and selects nothing (checked against Q1 99.9.9: `-M format:typst` on a document with `format: html` produced html); we follow our own metadata merge, where the runtime layer is the top layer, and Gordon's expectation that a scalar `format` names the configuration to use even when it is not the first one listed. A **map-valued** `format` in the runtime layer supplies settings only and never selects: the wasm preview settings are `{format: {html: {source-location: full}}}` and must not force every wasm preview to html. Like `--to`, a requested format takes part in the project format for book consolidation (FR3, FR11) and may name an undeclared format. Selecting and configuring in one invocation needs `--to` plus the map (`--to typst -M 'format:{typst:{toc:true}}'`): two `-M format:` values do not combine, the later wins. Q1 also uses `-M to:x` / `pandoc.to` as a fallback format when no layer declares one; that is not adopted (out of scope).
- **FR3 The scope default comes from the target, never from `--to`.**

  | Target | Default requested scope |
  |---|---|
  | `Full` (`q2 render` with no file, or the project root; `--static`; a book download) | `book` |
  | one active document (`q2 render ch1.qmd`, a preview page) | `chapter` |
  | `Subset` of several files (in a Book project, including every file of the project) | `chapter`, each file rendered on its own (but see the collapse rule below for non-consolidating formats) |

  `index.qmd` is an ordinary chapter, not the book. The requested format never changes the scope: `q2 render ch1.qmd --to typst` in an html book renders ch1 as a typst chapter; `q2 render --to typst` builds the whole typst book. **In a Book project, naming files does not mean "the whole project" for a consolidating format:** only no argument, or the project-root directory, is `Full`. `q2 render ch1.qmd ch2.qmd` renders each file on its own even when the two are every file of the book, and `q2 render sub/` is a `Subset` of the render-list files under `sub/`, each rendered on its own. `-M book-scope:book` with one or several named files gives one whole-book output, as Quarto 1 does.

  **The collapse rule.** `classify_inputs` (`render.rs:~416-421`) collapses "the named files cover every project file" into a whole-project render. It was written for websites (PR #149, Carlos) as a performance shortcut: a subset render of every file goes through the dependency-graph augmentation, "wasted work". It is harmless where a whole-project render and a subset of everything are equivalent, so it **stays for non-book projects** (a manuscript project maps to the default project type and keeps it). For a Book project it changes the meaning of the command when the format consolidates, because a whole-project render there is one merged book. So F5a skips the collapse in `classify_inputs` for a Book project (the function has the discovered project, so it knows the kind: `render.rs:363`, `project_kind()` at `project/mod.rs:2670`) and **re-applies it in the orchestrator's several-files branch (F5a-D3b) for non-consolidating formats only**, where each named file's format has been resolved: when the project is a Book, two or more files are named, the named files include every chapter, and every named file's resolved format is non-consolidating (html, revealjs, ...), the render is dispatched as a whole-book (`Full`) render, which is what makes the html multi-file pass build the crossref registry; any named non-members ride along as `extra_render_files` (FR22). If any named file's format consolidates (typst, epub) there is no collapse and the loop renders each file alone; mixed formats do not collapse. So naming every chapter of an html book keeps today's behaviour, and naming several chapters of a typst or epub book now renders each alone (a merged book needs `-M book-scope:book`).

  **Quarto 1.** Its CLI loops over the named files calling `render()` for each (`cmd.ts:129-290`: no collapse; it reports only the last output) and it has no `book-scope`. **Measured (Q1 99.9.9, spike A4):** for an html book `quarto render one.qmd two.qmd` writes one `_book/one.html` that contains both chapters and no `two.html`, so Q1 does not give independent chapter pages there; this epic still renders each named file on its own (decided) and records the difference. **Deliberate difference from Quarto 1** on a single named file: it renders the whole book whenever one file of a book with a single-file output format is named (`bookIncrementalRenderAll`, `book-render.ts:655-679`, used at `project.ts:169-181`) because it has no way to ask for one chapter. This supersedes parity E11 ("`q2 render ch1.qmd --to typst` keeps rendering the whole book").
- **FR4 The book rule for format selection.** `project_formats_only` = the project is a Book **and** the requested scope is Book. Then only the project's keys select (Q1's `projectFormatsOnly`, `book.ts:149`) and the requested format applies to every member. Otherwise the document wins (FR1). **Deliberate difference from Quarto 1,** which applies `projectFormatsOnly` to every render in a book: chapter scope is new in q2 and the chapter's own `format:` must be honoured in it. Consequences: `q2 render` of an html book renders every member as html even if `ch3.qmd` says `format: typst` (Q1 parity); `q2 render ch3.qmd` renders typst alone; `q2 render ch3.qmd -M book-scope:book` renders the whole book in the project's format; several named files render each in its own format. A `Full` render does not render non-members at all (the render list is cut to the chapters plus footer and 404 pages), so a non-member only shows the project format when it is such an addition; a **named** non-member page renders on its own, in its own format (FR22).
- **FR5 `book-scope` is ordinary metadata.** Top-level key `book-scope`, values `book` and `chapter`; never read from under `format.<x>:` (the format depends on the scope, so a format-specific scope would be circular). Layers: runtime > document > `_metadata.yml` > project (extension layers do not supply it). The document and `_metadata.yml` layers count only when exactly one file is the active document; with `Full` or several files only the project and runtime layers decide. An **invalid value** gets its own diagnostic and that layer's value is ignored (the next lower layer applies). Diagnostics, none of them errors, are also emitted for the cases where a value is ignored and the user would want to know: `book-scope` under `format.<x>:`; a project, directory or document `chapter` ignored in a whole-project render; `book-scope` in a project that is not a book. Absent means "the user did not choose": the target's default (FR3). `none` is not an accepted input (FR9). No write-back of the resolved value into the merged metadata in this epic; filters see what was requested. One function in `quarto-core` interprets a request's `book-scope` value (an object's top-level key to `Option<BookScope>`, invalid values reported); the resolver and the native routes\' captures pre-gate (F4-D3) both call it, so no site compares the raw string.
- **FR6 Explicit requests work in both directions.** A runtime-layer `book-scope` (an explicit request for this render) overrides the target's default: `book` with one or several files renders the whole book (Quarto 1's behaviour, on request; a book of only the named chapters is the future improvement in `bd-partial-book-scope-wrv9h219`); `chapter` with several files is the default. `chapter` with a whole-project render of a **Book project** is an **error** with an improved message that names the problem ("`book-scope: chapter` needs a file to render: name the chapter(s)"), since there is no chapter to choose. In any other project, and for a standalone document, a runtime `chapter` is an info diagnostic (FR5) and never an error: the project kind is checked first, and `render_single_doc` asks the resolver as `ActivePage(input)`. A project, directory or document `chapter` in a whole-project render is not an error either: it is ignored, with the info diagnostic of FR5, because it describes how to render one chapter, not the book.
- **FR7 No special scope paths remain.** Removed: `q2 render --book-scope` (use `-M book-scope:chapter`), `RenderArgs.book_scope`, `ProjectPipeline::with_book_scope` and its field, `PandocRequestInput.scope`, `ScopeParam` and the scope parameter of `may_render_book` on the native routes, the wasm `scope` request option, the `scope` arguments of the hub-client download code, `--static`\'s special "pass `book`", and the CLI's "every file named is a whole-project render" collapse in `classify_inputs` for Book projects (it stays for other projects, and the orchestrator re-applies it for non-consolidating formats, FR3). `ResolvedBookScope` and the `stats.book.scope` echo stay: they are output, not input.
- **FR8 Chapter and none scope use the document's own format.** `render_chapter_alone_summary` (`project/book/chapter.rs:82-104`) overrides with whatever format its caller passes; the wrong value comes from the orchestrator's call, `run_book_scoped` passing `&self.format` (`orchestrator.rs:~1115-1121`). The call site changes to pass the document's resolved format; the function's contract does not (its public sibling `render_chapter_alone` is used by the preview routes with an explicit requested format). The function also has to hand on the resolved *key*, not the base identifier: today it passes `format.identifier.to_string()` as the override (`chapter.rs:93`, used at `:103`), so a chapter whose format is an extension format such as `acm-typst` would render as plain `typst`; F5a passes `format.target_format` and tests an extension-format chapter, or records the limit. Html chapter renders keep today's path (`run_inner`, per document) and are not rerouted through the typst-oriented chapter-alone machinery; a deterministic test pins this (FR19).
- **FR9 `Page` becomes `none`.** `ResolvedBookScope::Page` is renamed; the wire string in `stats.book.scope` becomes `none`; the Rust variant name is chosen in F3c (a bare `None` is legal but reads like `Option::None` next to the `Option<BookScope>` code). `none` means "no book mode: the project is not a book, or the file is not in the chapter list". It is a resolution result and an echo, never an input; an input `book-scope: none` is an invalid value (FR5) whose message says so.
- **FR10 `Q-5-42` is narrowed, not removed.** It fires only when the winning `book-scope: book` came from the **runtime** layer (an explicit request for this render) and the format has no whole-book output (html, docx, pptx). Project, directory and document values, and the target's default, are silent. `chapter` on a non-consolidating format is honoured (a member of an html book is a chapter anyway) and never warns. The text is reworded for `-M`. This needs layer provenance from F2. It is emitted by one pure function, `scope_notices(request, membership, format, file)`, which also produces the Q-5-41 info and the non-member warning (FR22): `resolve_book_scope` calls it for the native routes and wasm, and the orchestrator's tail calls it only for the dispatches that did not go through `resolve_book_scope` (a non-consolidating format, html included, whose dispatch never reaches it, and the html partition of the several-files loop), so no notice is emitted twice. Per named file, Q-5-42 is emitted once.
- **FR11 Which format each site judges.** Requested scope Book: the project's format (project keys plus the requested format) for the dispatch (`format_consolidates_book`), Pass 1, `post_render` gating and the book merge. Requested scope Chapter: the document's resolved format for the dispatch, `post_render` gating and the css diagnostics. Pass 1 always runs under the project format (a book-wide index is a property of the book), held in a field separate from the dispatch format, which the nested chapter-alone pipeline also receives (so Pass 1 never runs under the chapter's format); `pass1_key` already includes `format_id`, so a different format cannot corrupt the cache. **Several named files** (a `Subset` of more than one file with a Chapter request in a Book project) have no single dispatch format, because each file has its own: the orchestrator branches for this case *before* the `format_consolidates_book(self.format)` test in `run_with_book_support`, with `self.format` set to the project format (it is used only for Pass 1 and the Q-5-33 skip), each file's resolved format decides how that file renders, `post_render` is gated on whether any output of the non-consolidating partition is html-based (not on `self.format`), and the CLI's "not yet supported" refusal gate runs per file (F5a-D3b). **Q-5-33** (a book cannot render to a format with no book support) applies only when the requested scope is Book; a chapter render to docx, pptx and the like is allowed. This is a deliberate behaviour change (`q2 render ch1.qmd --to docx` in a typst book now renders the chapter; hub-client's docx chapter download already has no gate); a whole-project `--to docx` is still refused. F5a verifies the gate's current conditions first. Extension formats (`acm-typst`) resolve their base through `parse_format_descriptor`; the gate lets unknown extension keys through today, and F5a records that rather than changing it.
- **FR12 One overlay mechanism.** `OverlayRuntime` (files only, from the parity epic's Plan 10; native-only and `#[async_trait]` today) is generalised to an immutable per-render overlay, `RenderOverlay { files, metadata }` (deriving `Debug`), that compiles for wasm too (module ungated, the same `cfg_attr` async_trait pair as `SystemRuntime`). Its `runtime_metadata()` is the inner runtime's metadata with the overlay's merged on top (objects recursively, overlay wins; a non-object overlay value replaces, so a scalar `format` replaces an inner map-valued `format`). **No identity check:** applying the same overlay twice is harmless (file reads resolve outer-first to the same bytes, `path_metadata` is unchanged through an inner overlay, and the recursive metadata merge is idempotent), so the nested chapter-alone pipeline needs no special case (`Arc<dyn SystemRuntime>` has no downcast hook, and adding one would touch a core trait for no observable effect). **One rule: whoever creates the runtime wraps it.** The creators are `render_single_doc` and `render_project` (not `render_once`, whose runtime only classifies the arguments), the preview route's `render_blocking` (at its top, before the book-scope resolver runs, with the overlay keyed by the canonical active path), `render_book_download`, and the wasm entries (`render_pandoc_request`, `render_single_doc_to_response`, `render_project_active_page_to_response`, the preview AST renderer, `render_page_for_preview`, `render_page_in_project_with_attribution`, `render_qmd` and `render_printable`, each of which must hand the wrapped runtime down to its project discovery). `ProjectPipeline::new`, `render_to_file` and `render_document_to_file` never wrap; the nested chapter-alone pipeline receives an already-wrapped runtime; `options.overlay` is only what a creator reads. F1 lists each site, tests that the metadata reaches a consumer at each, and unit-tests the wrapper's double application ("double apply behaves as single apply"). Per-request values never touch process state (the preview server renders a PDF preview and a book download concurrently). `-M KEY:VALUE` is wired in (today it is declared at `main.rs:68` and dropped by the `..` of the `Commands::Render` match arm, `main.rs:~1417`): the first `=` or `:` separates key from value, as in Quarto 1 (`flags.ts:507-515`); the value is parsed as YAML; a missing separator is an error. The canonical JSON of the full runtime metadata is hashed into `pass1_key` (native only, wasm has no cache). Known limits, documented: the runtime layer is built from JSON, so YAML tags are lost and path-valued keys are not rebased relative to the document.
- **FR13 Environment defaults** (what each environment supplies; the overlay carries only *explicit* choices, the target carries the rest):

  | Environment | Target | Overlay `book-scope` |
  |---|---|---|
  | `q2 render` (no file) | `Full` | none |
  | `q2 render ch1.qmd` | one document | none (default `chapter`) |
  | `q2 render ch1.qmd ch2.qmd`, `q2 render sub/` | `Subset` | none (default `chapter`, each on its own) |
  | `q2 preview --static` | `Full` (a file inside a project previews the whole project) | none (default `book`) |
  | live `q2 preview` viewer (SPA) | `ActivePage` | none for html pages; the PDF pane sends `chapter`, explicit; the CLI's `-M` is merged under it (FR20) |
  | embed PDF pane | `ActivePage` | `chapter`, explicit: a document's own `book-scope: book` must not turn a PDF preview into a book |
  | hub-client Download menu | `ActivePage` | the user's pick: `book`, or `chapter` ("This chapter only" and the plain entry of a consolidating format); nothing for other formats |

  On the wire (native routes, wasm), the per-request value travels as a generic `metadata` object, not a scope field; the server or wasm entry builds the overlay. The native routes\' async-side captures pre-gate reads the request's explicit `book-scope` through FR5's interpretation function (an explicit `chapter` skips loading every capture, as the PDF pane does today; otherwise a consolidating format loads them, even when no `book-scope` was sent: a document, directory or project `book-scope: book` would otherwise render a book with empty captures, at the cost of one full capture read per such request; F4 comments this and tests it). A stale embedded SPA still sends `{scope: 'chapter'}`, which is now ignored, so its PDF requests load every capture and its "Download book" click renders a chapter; F4 logs an unknown `scope` key at debug level.
- **FR14 One layer collector, shared with `MetadataMergeStage`.** A function in `quarto-core` returns the ordered, unflattened layers with their provenance (extension contributions, project, extension format metadata when a target format is given, the `_metadata.yml` chain, document, runtime). The stage flattens them as it does now; the resolver reads only the top-level `format` and `book-scope` keys, and only from the project, `_metadata.yml`, document and runtime layers (it never discovers extensions: FR5, and an extension's `contributes.metadata` that carries `format:` is a documented, tested exception where stage and resolver can differ). The document layer can be built from a content override with one front-matter helper (the four existing front-matter parsers are not reduced to one by this epic, but the resolver and the collector use a single new one, tested for agreement with the stage). `_metadata.yml` `format:` keys count as document-level keys (FR1). `output_ext::resolve_output_ext` moves onto the same layers (it currently sees only front matter and project). Profiles reach the resolver through the discovered `ProjectContext`; tests prove it for `--profile`, `QUARTO_PROFILE` and `profile.default`.
- **FR15 Wasm and hub-client.** The wasm entries stop re-detecting the format from front matter: they call the resolver with the editor buffer as content override and the project from the VFS (not the VFS copy of the open file). The preview pane is chapter scope. `classifyPreviewMode` and the SPA's `isTypstPdf` use the Rust-resolved key and class, not `meta.format` or `formats[0]`, and the classifier is called before `getQ2Format`'s early return for html. The wasm result keeps the full key list (the Download menu needs the non-first keys' `output-ext`) and the `book` field the menu reads. The SPA's only render entry, `render_page_for_preview`, gains a trailing options argument. Project discovery on every parse is cached, keyed by the discovered project directory plus a generation counter that lives inside `VirtualFileSystem` (not in `WasmRuntime`\'s wrapper methods: `with_vfs_mut` hands out the VFS itself). The rule is inverted so a new kind of file cannot be forgotten: a write does **not** bump only if it is a content edit of an existing `.qmd`, `.md` or `.ipynb`, or the path is under `/.quarto/` or `/__quarto_resources__/`; everything else bumps (a create or remove of any other path, config files, a brand file named by the `brand:` key, the extensions directory, `clear*`). Measure before and after with the same release artifact.
- **FR16 `--static` watcher.** The boot render and every watcher re-render go through the same resolver path as `q2 render`, with the project as target (a file argument inside a project previews the whole project, opened on that page, as Quarto 1 does; the file argument never reaches the render). For a consolidating format a change re-renders the whole book (the viewer serves the book): the policy is `rerender_action(is_consolidating_book, action)`, applied at the single point where re-render arguments are built; the recorded action stays the original one (so the browser still navigates as for a page change), and the book flag and project format come from the last render's report. For html the watcher keeps its per-document re-render as today, which under FR3 is a chapter render: it does not resolve cross-chapter references (`bd-html-chapter-xref-szfxmvyg`, outside this epic; the epic neither causes nor worsens it). When a render produces no outputs the browser shows the render failure, not "no index.html". `check_servable_format` judges the resolved project format (and `--to`): html, revealjs and typst are servable; epub, docx and pptx stay refused, because there is no good way to preview them, so the whole-book `--static` fixtures are typst, not epub. `-M book-scope:chapter` on a Book project (a directory, or a file inside one) is the FR6 error: the boot render aborts and the process exits 1 with the message, because the flag is fixed for the session and can never work (a failure page is reachable only on re-renders). Lazy execution on `--static` is driven by html page views, so code in a typst book's chapters stays inert there; recorded, not fixed.
- **FR17 Test runner and fallback.** `quarto-test`\'s runner switches to the resolver (it currently defaults a Book to typst while `render_once` defaults to html); the fallback is `html` everywhere, as in Q1. The runner always passes its resolved format as `with_format_override(Some(format))` (`runner.rs:~503`), which bypasses FR1 selection; F5b decides it passes only an explicit spec format. F5b audits the smoke fixtures that relied on the typst default.
- **FR18 Q-20-8 is a "not yet supported" notice.** Rendering several formats from one invocation does not work well yet; the diagnostic says so without promising a date. It is fed by the resolver's key list and so also fires for a project-level `format: {html, typst}`, where the skipped formats really are skipped; naming one with `--to` or a scalar runtime `format` keeps it quiet. ## Execution model

Same as the parity epic's, with two lanes.

- **No orchestrator.** There is no orchestrator process. Each plan's agent knows its own lane, the plan before it and the plan after it from the plan's `Lane`, `Start gate` and `Next in lane` lines, so nothing coordinates the lanes at run time. Plans are developed with **no sub-agents**, and an agent runs **at most one plan per session**: finish, report, stop; the next plan is a new session that starts with its own gate. **The Handoff log is the only channel to later plans** (a plan's agent reads the logs of the plans it waits on; nothing else carries state). Nothing in a plan blocks on a question to Gordon: every step that used to ask now states a default (a failed gate or precondition is reported in the final message and the agent stops; the non-member output location stays under `_book/`; the workspace nextest is recommended in the final summary and never run unprompted; the changelog, the epic checklist ticks and the push are Gordon's and never block a plan).

- **Where.** The integration branch lives in `.worktrees/workspace-7` and holds a clean tree; it only receives fast-forward merges. Two lanes, one per worktree, one agent per plan, one plan at a time:
  - **lane A (`.worktrees/workspace-3`):** F1, F3a, F3b, F5a, F7
  - **lane B (`.worktrees/workspace-6`):** F2, F3c, F4, F6, F5b, F8

  Lane B has slack after F3c until F3b lands (F4 waits on it); lane A idles after F3b until F4 lands, and again before F7 until F5b, F6 and F8 land. Land F3a, F3b and F4 promptly: everything after them waits on them. Both worktrees were pre-staged on 2026-10-15 (`npm install` run, so `node_modules` is warm; workspace-3 currently holds the planning branch, workspace-6 a staging branch).
- **Taking a plan.** An agent starts its plan only when the plan's start gate prints `ready`; otherwise it reports what is missing in its final message and stops, and a new session starts the lane when the prerequisites have landed. Every gate checks both that the plan's own file is on the integration branch (a lane must never start from a tip that lacks the epic and its plan) and the landing tags of the plans it waits on, and prints `ready` only if nothing is missing; the gates of F1, F2 and F3c (the plans that wait on no tag) also print `git status --short` so a dirty lane is visible. Gates locate the worktree from the repository, so they run from anywhere (`cd "$(git rev-parse --path-format=absolute --git-common-dir)/../.worktrees/workspace-N"`). Each plan's agent reads this epic, the research note's §7, its plan, and the Handoff log of every plan it waits on.
- **Landing tags.** `git branch --merged` is not a safe gate (a freshly cut branch with no commits of its own counts as merged). Each plan, when it lands, tags the landed tip `fr-landed/<id>` (for example `fr-landed/f3a`), and start gates test that the tag is an ancestor of the integration branch.
- **Initialising the worktree** (each plan repeats the commands with its own names). Workspace-3 is a free lane only after the planning files exist on the integration branch (every gate checks this by the plan's own file, so a rebased or cherry-picked planning branch also passes).

## Cross-cutting rules

- No braid strands for in-plan work. Strands only for things found outside every plan (FR19 lists the ones already known; F7 files the rest).
- Per task: `cargo clippy -p <crate> --all-targets -- -D warnings` plus `cargo nextest run -p <crate>` (Rust); `tsc` plus `vitest` in the touched package (TS), and the plan-end gates of the landing procedure. New Rust integration tests go in `crates/<crate>/tests/integration/<name>.rs` plus `pub mod` in `main.rs`, alphabetised.
- Test fixtures must not need `knitr` or a network typst-package download. For whole-book `q2 render` tests use a consolidating format that needs only pandoc (`epub`); `--static` refuses epub (nothing to browse), so its whole-book fixtures are typst. A whole-book typst render ignores `output-ext: typ` and still runs `typst compile` (measured, spike A7), and it stages `@preview/orange-book` (network or cache, not isolated: A8), so a whole-book typst fixture needs the `typst` binary **and** that package; F5a writes none and F5b has at most one end-to-end; `typst` book fixtures with `output-ext: typ` are for chapter-alone and for asserting on the `.typ`. Tests that need `pandoc` or `typst` **skip when the binary is absent**, as the existing ones do (`book_scope_cli_e2e.rs`, the `require!` macro in `book_download.rs`); a skip is a silent early return, not a pass, and each plan's Handoff log says which of its tests need which binary; CI installs both on Linux and macOS. Making CI fail on a missing binary is a repo-wide change and not part of this epic. The orange-book smoke fixture is gated on `knitr` and stays as it is.
- Tests do not call `std::env::set_var` (the repo avoids it): supply a profile in-process through `_environment` or `profile.default`, and spawn the binary with `.env("QUARTO_PROFILE", ..)` for the environment-variable case.
- Cross-platform: gate platform-specific test helpers as the repo rules say; never glob `$TMPDIR`; use `Path`/`PathBuf` (no hard-coded separators) in new code and fixtures.
- Never `#[cfg(any(target_arch = "wasm32", test))]`; async traits stay `#[async_trait(?Send)]` (the overlay module's `cfg_attr` pair mirrors `SystemRuntime`\'s); editing the wasm Lua files means updating `crates/pampa/tests/wasm_lua.rs` (not expected here).
- **Changelogs:** no plan edits `hub-client/changelog.md`. Gordon cleans the changelog in one pass before filing the PR (too many entries, too technical, hashes made stale by the repeated rebases; it is part of his `/git-revise` workflow), so the AGENTS.md two-commit workflow is not followed inside this epic. Plans record user-visible changes in their Handoff log and in the docs; there is no CLI changelog. Nothing blocks a plan that does not edit the changelog: the `changelog-reminder.sh` hook only emits a reminder, and only when the edited path is `hub-client/changelog.md`; no CI workflow or lint rule checks it.
- New or changed error codes: catalog entry, `docs/errors/<subsystem>/<code>.qmd` and the `docs/_quarto.yml` sidebar entry in one commit (the `error-docs-*` lint rules). This epic adds the `book-scope` diagnostics (F3a) and the non-member warning (F3b), and rewords Q-5-41, Q-5-42 (F3b) and Q-20-8 (F5a); it adds no code for the preview pseudo-formats (FR21).
- Never push without Gordon's approval.
