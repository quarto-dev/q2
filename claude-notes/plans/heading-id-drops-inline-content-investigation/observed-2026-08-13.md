## 3. Adjacent divergence found while probing (`probes/probe2.qmd`)

| heading source | Pandoc | q2 | |
|---|---|---|---|
| `## 1 leading digit` | `leading-digit` | `1-leading-digit` | ✗ |
| `## .leading dot` | `leading-dot` | `.leading-dot` | ✗ |
| `## with ... dots` | `with-dots` | `with-dots` | ✓ |
| `## trailing dots ...` | `trailing-dots` | `trailing-dots` | ✓ |
| `## $x$ only math` | `x-only-math` | `only-math` | ✗ (this bug) |

Two separate facts here.

**(a) `dropNonLetter` is missing.** Pandoc's `inlineListToIdentifier` ends
with `dropNonLetter`, which strips every leading character up to the first
*letter*. q2's slug filter (`autoid.rs:42-57`) has no equivalent, so an id
can begin with a digit or a `.`. This lives in `auto_generated_id`'s filter,
not in `collect_text` — a different defect in the same function, and *not*
what this strand is about. Flagged as a design question, not assumed in scope.

**(b) The `bd-ellipsis-not-smart-48bv2pe6` closing note is now stale.** That
note recorded, as a deliberately-unfiled finding, that "q2 gives
`heading-with-...-dots` where Pandoc gives `heading-with-dots`". PR #518
(the grammar fix that made a dot run lex as one token) fixed it as a side
effect: q2 now converts the run to U+2026, which its slug filter drops just
as Pandoc's does. Both dot rows above agree. Nothing to file.

## 4. Downstream consequence: empty ids and bogus `-1` / `-2` suffixes

`probes/probe3.qmd` — three headings whose content is *entirely* one of the
dropped kinds:

```markdown
## $x$

## ~~gone~~

## [also gone](https://example.com)
```

| | Pandoc | q2 |
|---|---|---|
| section 1 | `<section id="x">` | `<section class="section level2">` — **no `id` at all** |
| section 2 | `<section id="gone">` | `<section id="-1">` |
| section 3 | `<section id="also-gone">` | `<section id="-2">` |

`collect_text` returns `""` for all three, so `base_id` is empty; the
dedup counter at `postprocess.rs:946-952` then hands out `""`, `-1`, `-2`.
The first heading is not linkable at all, and the other two get ids that
carry no relation to their text. This is the interaction the strand
predicted ("two headings that differ only inside a dropped span now
collide"), in its most extreme form.

**Pandoc has an empty-id fallback that q2 lacks.** `probes/probe4.qmd`,
two headings that are nothing but an image with empty alt:

| | Pandoc | q2 |
|---|---|---|
| section 1 | `<section id="section">` | `<section class="section level2">` — no `id` |
| section 2 | `<section id="section-1">` | `<section id="-1">` |

Fixing `collect_text` removes the *cause* for the probe3 cases (all three
recover real ids) but not for probe4, where the text genuinely is empty.
Whether to add Pandoc's `section` fallback is a scope question below.
