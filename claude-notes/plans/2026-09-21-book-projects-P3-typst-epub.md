# Plan: Typst + EPUB book output, DOCX/PPTX scope-out (book-projects P3)

**Date:** 2026-09-21
**Epic:** [`2026-09-21-book-projects-epic.md`](2026-09-21-book-projects-epic.md)
**Design (authoritative):** [`../designs/book-projects-architecture.md`](../designs/book-projects-architecture.md) §6, §11
**Q1 ground truth:** `tests/docs/smoke-all/typst/orange-book` (and `orange-book-lang`/`orange-book-margin`/`override-orange-book`) — the deepest numbering-correctness fixture in Q1's own test suite, with machine-checked `.typ`-source and PDF-text assertions covering every crossref-numbered construct type.

## Overview

Wire P2's merge mechanism through the two real single-file book formats end-to-end, and make the currently-silent "book doesn't support docx/pptx" gap into an explicit diagnostic instead. This phase is mostly wiring — P2 already did the hard part (a format-agnostic merge that hands off to the unmodified single-document pipeline).

## Decisions

- **Chapter-scoped numbering and appendix-lettering for Typst are not "already vendored and working" the way brand/CSS/templates are** — they depend on the Typst book extension's own filter (`orange-book.lua` or a sibling), not on Quarto's generic vendored Lua (see design doc §5, corrected during review: an earlier draft of P2 mis-cited `book-cleanup.lua`'s own comment, which is wrong). P2 vendors `orange-book` locally as a test fixture and emits the comment markers it needs; this phase is where that fixture actually gets exercised end-to-end through a real Typst compile, not assumed to "just work" because the rest of the Typst pipeline already does.
- Full Q1 feature parity is the target for Typst (matching `feature/pandoc-writer-hybrid`'s own typst plan's stated end state) — brand/CSS mapping, templates, packages are already vendored and working for single documents; this phase just confirms they work unchanged for a *merged* document.
- EPUB gets chapter splitting via `--split-level` automatically once the merged document has real per-chapter H1s — no book-specific EPUB code beyond confirming the split boundary matches book chapter boundaries (not, e.g., every H1 including sub-chapter headings if `epub-chapter-level` differs from 1).
- **`epub-cover-image` derivation**: when `book.cover-image` is set and no explicit `epub-cover-image` is present, derive one from the other. **Corrected by a ground-truth-verification pass — this is not actually a "direct port" of `epubBookExtension.onSingleFilePreRender`, though the target is still the right one for Q2's architecture.** Reading `format-epub.ts` directly: Q1's function writes `format.metadata[kBookCoverImage]` (`kBookCoverImage = "cover-image"`, a *generic* Pandoc metadata key that Pandoc's own EPUB writer reads natively) — it never writes `format.pandoc["epub-cover-image"]` anywhere in Q1's codebase. Q2 has no equivalent generic `cover-image` pass-through for EPUB; the already-landed `feature/pandoc-writer-hybrid` work only forwards a key literally named `epub-cover-image` (as a `--epub-cover-image=` CLI flag). So P3's mechanism is a deliberate *adaptation* to Q2's existing architecture — derive Q2's `epub-cover-image` key from `book.cover-image` — not a literal port of Q1's mechanism, which targets a different, pandoc-native metadata field Q2 doesn't special-case. Don't go looking for a `cover-image`-keyed mechanism to port; there isn't one to reuse.
- DOCX/PPTX book targets: explicit diagnostic via P1's general `BookProjectType::is_supported_format` rule (port of Q1's `projectFormatsOnly`/`isSupportedFormat`) — not a one-off special case for these two formats, and not a silent per-chapter fallback (Q1's own default behavior there is arguably a footgun, not a feature worth reproducing).
- LaTeX/PDF: not implemented (out of scope per epic), but P2's `top-level-division: chapter` lever was deliberately built generically so this is a small follow-on later, not a redesign.

## Checklist

### Tests first
- [ ] Reduction of `orange-book`'s numbering torture-test (figures, tables, equations, theorems/lemmas/definitions, listings, labeled callouts, sub-figure panels, a custom `crossref.custom` kind) rebuilt as a Q2 fixture, rendered via the real `q2 render <book> --to typst` end-to-end path against the *unpatched*, locally-vendored `orange-book` extension (P2's fixture — this phase is where it's actually exercised, not P2), asserting chapter-scoped numbers ("Figure 1.1", "Figure 2.1" resetting per chapter, "Theorem A.1" for appendices, "Figure 2.1a"/"2.1b" for sub-figure panels) against the compiled PDF text or intermediate `.typ` source.
- [ ] Test: a cross-chapter reference within the merged single-file document (e.g. chapter 3 referencing a chapter 1 figure) resolves to the original chapter's number — this is "free" per §6 but must be asserted, not assumed.
- [ ] Test: EPUB book render produces one `.epub` with chapters split at `book.chapters` boundaries; unzip and inspect `EPUB/text/*.xhtml` count and content, mirroring `feature/pandoc-writer-hybrid`'s own `e2e_render_epub_chapter_level` methodology.
- [ ] Test: both Typst's and EPUB's unified bibliography (one merged reference list *and* correct in-text citation numbers, not per-chapter) — built by P2's citeproc-deferral fix (design doc §6), not automatic (an earlier draft of this epic wrongly assumed it was free; see the epic doc's revision history). Assert it end-to-end for both formats, don't assume it.
- [ ] Test: `book.cover-image` set, no explicit `epub-cover-image` — the rendered `.epub`'s OPF manifest marks the derived cover with `properties="cover-image"`.
- [ ] Test: `q2 render <book> --to docx` produces a clear diagnostic naming the unsupported combination, not a silent per-chapter render and not a panic.
- [ ] **Integration test, compiled-artifact half of P2's cross-artifact invariant check** (ownership split clarified by a review pass — P2 tests the data-level invariant; this is the half that needs a real compile, which is this phase's job): for a fixture with an appendix chapter, the appendix letter P1 computed for the sidebar (via P4's multi-file path, or by inspecting the sidebar structure directly) matches the appendix letter `orange-book` actually produced in the compiled single-file Typst PDF for that same chapter. This closes design doc §4's "provably equal by construction, but nothing tests it" note.
- [ ] **Integration test, the invariant's second half — added by a ground-truth-verification pass that found the design doc's original premise false**: a fixture with an `.unnumbered` individual appendix chapter (not the synthetic "Appendices" divider — a real appendix chapter, unnumbered on its own), rendered through single-file Typst mode. Confirm whether `orange-book`'s appendix show-rule skips it the same way `sections.lua` skips an unnumbered ordinary chapter for numeric numbering (design doc §4). If it does, this is a straightforward regression guard. If it *doesn't* — i.e. the unpatched extension still assigns it a letter — that's a real, previously-unknown Q1-fidelity gap this epic needs a decision on (diagnostic, documented limitation, or a fix), not something to leave silently discovered by this test alone.
- [ ] **Resolved with the user (fifteenth pass), no longer an open test/decision**: a Typst book target with no `format.typst` extension configured now auto-resolves to the vendored `orange-book` (P2's Decision, mirroring Q1's own zero-config default) rather than silently degrading — the diagnostic-vs-documenting-test fork this item used to pose no longer applies to the default case. P2 owns the auto-default mechanism and its own end-to-end test (a book with no extension configured renders/compiles successfully via `orange-book`); this phase's job is to confirm that test actually exercises a real `--to typst` invocation end-to-end (not just the merge/attribute-stamping mechanism P2 tests directly) as part of this phase's own end-to-end verification pass.

**End-to-end verification (this repo's standing rule, not optional):** render the reduced `orange-book`-style fixture via `cargo run --bin q2 -- render <fixture> --to typst`, then actually open/inspect the compiled PDF (not just the intermediate `.typ` text) for at least the chapter-scoped figure numbering and the appendix lettering, and do the same for a real `--to epub` render (unzip, inspect XHTML). Record the exact invocation and what was inspected in this plan's checklist as each item completes, per the repo's end-to-end verification convention.
