## Goal

`resolve_book_scope` works from the requested scope the resolver computed (F3a) and nothing else; one pure function, `scope_notices`, decides every `Q-5-41` / non-member-warning / `Q-5-42` diagnostic for every format, so no site emits them twice; Q-5-42 is narrowed to an explicit request and Q-5-41 is reworked for named non-member pages (a quiet info for any chapter-scope request, a warning for an explicit runtime `book`); the CLI flag and the Rust-side scope plumbing are gone; the native routes and the wasm entry still *receive* a `scope` on the wire until F4, and this plan leaves an adapter at exactly those two call sites.

## What exists (verified 2026-10-15 in the parity tree; round-5 corrections folded in)

- `resolve_book_scope(project, active, scope: Option<BookScope>, format, runtime)` (`project/book/scope.rs:107`) returns `BookScopeResolution { scope: ResolvedBookScope, membership, diagnostics }`: a non-book project is the "no book" value silently (`scope.rs:119-121`); a non-consolidating format is `Chapter` for a member and "no book" otherwise (with Q-5-42 for an explicit `Some(_)`); a consolidating format with an explicit `Chapter` is `Chapter` (or "no book" for a non-member, **no notice today**); otherwise a member is `Book` and a non-member "no book" with Q-5-41 (`not_a_chapter_notice`, `scope.rs:160`: "This page is not part of the book ... rendered as a standalone document instead of as part of the book"). After F3c the "no book" value is `none`. `book_membership` (`scope.rs:35`) is pass-free and returns `BookMembership { chapters, active_is_chapter }`.

## Known limitation this plan inherits

Cross-chapter `@ref`s do not resolve in html chapter or non-member renders today (`bd-html-chapter-xref-szfxmvyg`, open, outside this epic; FR19; the Chapter default for html and FR15 depend on it). The reworked `Q-5-41` text says a non-member "cannot link to the book's chapters" on purpose: it states the end state, and it is already true for chapter renders in html until that strand lands. F3b does not fix it and its tests must not assert resolved cross-chapter links for html.

## Decisions

- **F3b-D1 `resolve_book_scope` takes the request and calls `scope_notices`.** Signature: `resolve_book_scope(project, active, request: &ScopeRequest, format, runtime)`; the target's default (FR3) is already inside `request.value`, so the old "no explicit scope means Book for a member" rule becomes "the request is `Book`". Resolution is otherwise unchanged: non-book → `none` (silently); non-consolidating format → `Chapter` for a member, `none` otherwise; consolidating format → `request.value` for a member (`Book` or `Chapter`); for a **non-member** (in the project, not a chapter: FR22) the result is `none` for every request and every format, and the file renders as a standalone page. The diagnostics come from `scope_notices` (D2), not from code inside `resolve_book_scope`. A non-member is detected the same way for every format (membership is pass-free, `book_membership`, `scope.rs:35`).
- **F3b-D2 One pure function decides every notice; two call sites, never both.** `scope_notices(request: &ScopeRequest, membership: Option<&BookMembership>, format: &Format, file: Option<&Path>, project_dir: &Path) -> Vec<DiagnosticMessage>` (the exact shape is the agent's to settle; it takes no runtime, does no I/O, and `membership` is `None` for a non-book project, which gets no notices from it) is the **only** place that builds `Q-5-41`, the new non-member warning and `Q-5-42`. For each named file at most one of them is produced:
  - A **member** of the book, or a render that names no file (`file` is `None`: a `Full` render, which has no per-file notices but can still be asked for a `book` the format cannot honour): `Q-5-42` iff `request.explicit == Some(LayerKind::Runtime)`, `request.value == Book` and the format has no whole-book output (html, docx, pptx). A default request, and project, directory or document values, are silent; `chapter` on a non-consolidating format is honoured and never warns. New text for `-M` (problem: "`book-scope: book` was requested for this render, but `{format}` has no whole-book output, so each page is rendered on its own.").
  - A **named non-member** in a Book project, in **any** chapter-scope situation (the default `Chapter`, an explicit `chapter` from the runtime, the project, `_metadata.yml` or the document, any format): the reworked `Q-5-41`, a **quiet info**: "`{file}` is not a chapter of this book, so it was rendered on its own: it has its own numbering, and it cannot link to the book's chapters", with the existing hint to add the file to `book.chapters`. This **replaces** the old rule that an explicit `chapter` on a non-member shows nothing: the notice states a fact about the output, not about what was asked. An explicit **runtime** `book-scope: book` on a non-member gets instead a **warning** (a new code allocated here): "`book-scope: book` was requested, but `{file}` is not in the book's chapter list, so it was rendered on its own". (The warning supersedes `Q-5-42` for that file: one diagnostic per named file.) A `book` that came from the project, directory or document layer is not an explicit request for this render and gets the info.
  - The wording is a first draft; refine it when the code is in hand. Catalog entries, docs pages and sidebar entries change together in one commit.

  **Call sites.** `resolve_book_scope` calls `scope_notices` and returns the result in `diagnostics`: that serves `run_book_scoped`, the pandoc-request entry (native and wasm) and `render_blocking`. The orchestrator's tail (today it emits `Q-5-42` for any project that was handed a scope, `orchestrator.rs:1070-1080`; it now emits only for a Book project, since `scope_notices` yields nothing without a membership) calls `scope_notices` **only for dispatches that did not go through `resolve_book_scope`**: a non-consolidating format (html, docx, pptx: the html dispatch never reaches `resolve_book_scope`) and, after F5a, the per-file loop's non-consolidating partition (F5a-D3b; F5a calls this function once per named file). `run_book_scoped` therefore records that its notices were already emitted, so the tail does not repeat them. A test pins "exactly one notice, no duplicates" for a named non-member in an html book (tail path) and in an epub book (`run_book_scoped` path), and for a member with an explicit runtime `book` on html.
- **F3b-D3 The dispatch reads the scope from the resolver.** `ProjectPipeline` already computes the request through `resolve_render_scope` using its `RenderMode` (F3a-D2); its `book_scope` field and `with_book_scope` are removed and the dispatch uses that request; the Q-5-33 gate applies when the requested scope is `Book` (the narrowing itself lands in F5a, which owns the orchestrator's format decisions; F3b keeps the gate's current conditions).
- **F3b-D4 Adapters (removed in F4).** The native routes and wasm still hand the old `scope` to Rust. Each call site turns it into a `RenderOverlay` with `{ "book-scope": "book" | "chapter" }` (from F1) and passes that on; nothing downstream of them sees a scope parameter. The routes always render with an active document, so their target is `ActivePage`; the explicit runtime value decides between chapter and book (an explicit `book` with one active document renders the whole book: FR6). Following F1's single rule (the code that *creates* a runtime wraps it, and nothing downstream wraps again): on the preview route the adapter and its overlay apply **at the top of `render_blocking`** (`render_helper.rs:412`), keyed by the canonical `active` path (the overlay's file key is normalised lexically only, `overlay_runtime.rs:46-57`), **before** `resolve_book_scope` (`:429`) so the resolver, `render_chapter_alone` (`:224-226`) and `render_document` all see the overlay; the wasm adapter applies it in the entry that creates its runtime. Mark each adapter `// F4: delete with the wire change`.
- **F3b-D5 Lua and filters see the request.** Because `book-scope` is ordinary metadata a filter reads it from the merged metadata; what it sees is the *requested* value (or nothing when only the target's default applies), not the resolved one (FR5, no write-back).
- **F3b-D6 One interim check stays.** With `--book-scope` gone, `-M book-scope:chapter` names no file-count rule of its own, but until F5a loops over several named files the book dispatch would silently merge the whole book for two or more files. `render.rs` therefore keeps a check that an **explicit runtime** `chapter` request names exactly one file (`// F5a: delete`), now keyed on the overlay value instead of the removed flag. It guards only that explicit case: **several named files without any request** still merge the whole book in a consolidating format (`run_book_scoped`'s fall-through, `orchestrator.rs:1096-1100`) although the default request is now `Chapter`; that is today's behaviour and F5a replaces it. The Handoff log says so. F5a deletes the check and the test that pins it.
