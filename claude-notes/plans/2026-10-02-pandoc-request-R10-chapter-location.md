## Open decisions for Gordon

- **Q-10-1 — marker or outline? (found while writing this plan; it refines the "okay" you gave to the outline approach). Evidence now collected (planning pass 2, 2026-10-02); the STOP stays yours.** The first-round decision was a Rust-computed chapter map plus PDF-outline navigation with no `typst.lua` edit. Facts, all from experiments with typst 0.14.2 (the version the browser targets), on a real `q2 render` of a 4-item orange-book book (index, two chapters, one in a subdirectory, one appendix chapter):
  1. Labels, including `<id>` heading labels and `#metadata(...) <label>`, are **not** exported as PDF named destinations (no `/Dests` or `/Names` in the file); the PDF carries only an `/Outlines` tree, whose entries pdf.js resolves to explicit page destinations.
  2. A queryable marker gives the **page number** directly: `#context [#metadata((file: "ch1.qmd", kind: "chapter", page: here().page())) <q2-book-chapter>]` compiles, and `typst query doc.typ "<q2-book-chapter>" --field value` returns `[{"file":"index.qmd","kind":"chapter","page":5},{"file":"one.qmd",...,"page":7},{"file":"sub/two.qmd",...,"page":9},{"file":"app.qmd",...,"page":13}]`. These are the physical pages (checked with `pdftotext -f N -l N`: page 5 starts "1. Preface", 7 "2. One", 9 "3. Two", 13 "A. Appendix A"), which is what pdf.js's page number is.
  3. **The marker goes after the heading, as drafted.** The same markers placed *before* each heading report pages 3, 5, 7, 11, two pages too early, because orange-book's chapter heading rule starts a new page. The default book template is `orange-book` (`extension/discover.rs:347`, `TYPST_BOOK_DEFAULT_EXTENSION`), so a book never renders with typst's plain template unless the author overrides it; orange-book is the template to test.
  4. **The markers change nothing visible**: `pdftotext -layout` and `-bbox` of the marked and the unmarked PDF are identical apart from the creation date, and the page count is the same.
  5. **The browser compiler can query.** `@myriaddreamin/typst-ts-web-compiler` 0.7.0 exposes `TypstCompiler.query(main_file_path, inputs, selector, field)` and `TypstCompileWorld.query(kind, selector, field)`. The wrapper's one-shot `compiler.query({mainFilePath, selector, field})` **does not work** in `@myriaddreamin/typst.ts` 0.7.0: it throws `document is not compiled` (it snapshots a world without compiling) and double-`JSON.parse`s. What works, run in Node 24 against lane H's `node_modules`: `compiler.runWithWorld({ mainFilePath }, async (w) => { await w.compile({ diagnostics: 'full' }); const q = await w.query({ selector: '<q2-book-chapter>', field: 'value' }); const pdf = w.pdf({ diagnostics: 'full' }); ... })` returns `[{"file":"one.qmd","page":1},{"file":"sub/\"two\".qmd","page":3}]` for a small document whose file names contain a quote (the escaping is preserved) and one `compile` serves both: the query took ~3 ms and the PDF export ~26 ms after a ~41 ms compile (fontless test document). So H8's session (`ts-packages/typst-host/src/session.ts:220` calls `compiler.compile({ ..., format: 1 })`) switches to the `runWithWorld` form for book requests and pays no second layout.
  6. **The outline fallback works but the drafted ordinal rule is wrong.** pdf.js 6.3.289 (`pdfjs-dist`, the version H9 plans) on the native PDF gives `getOutline()` = `1. Preface` (p5), `2. One` (p7), `2.1 Sub one` (p7, depth 1), `3. Two` (p9), `Appendices` (p11), `A. Appendix A` (p13), all explicit destinations. The **appendix divider and any part divider are depth-0 outline entries with no file**, so "the entry at the same ordinal among file-bearing items of that depth" lands on the wrong entry from the appendix on. The contract below matches by title (number prefix stripped) first and uses the ordinal only to break ties among equal titles.

  **Recommendation:** use the marker (primary) with the outline as the fallback, both described below. Still no edit to the vendored `typst.lua`: the marker is a `typst` raw block that Rust inserts into the merged AST **only for `pdf` requests** (`RequestPost::CompileTypst`), so the `.typ` download and native `q2 render` stay byte-identical. The outline path needs the Rust chapter map to predict which headings are bookmarked, which user filters in pandoc.wasm can invalidate; the marker is exact because typst itself reports the page. Costs: the typst worker must run the `runWithWorld` form above, and the PDF's source gains a few lines of typst. If you prefer the outline alone, as first agreed, tasks 3 and the `chapterPages` parts of the contract drop out and nothing else changes. **The task-1 spike below is therefore already answered; it remains a STOP until you confirm.**

## Overview

R9 makes a book chapter's PDF the whole book. This phase says where the active chapter is in it, so the viewer (host H9) can open the PDF at that chapter. EPUB gets nothing (no viewer). The phase also fixes the contract between Rust, the typst worker and H9, since three agents in two lanes consume it.

## Anchor contract

Written here once; H8 and H9 point at it.

**`stats.book` in the `render_pandoc_request` envelope** (added by R9 for `scope`, extended here; `null` for a non-book or chapter-alone result):

```
stats.book = {
  scope: 'book' | 'chapter',
  chapters: number,                 // file-bearing items in the book (R9)
  active: number | null,            // index into `items` of the active chapter; null when the active page is not a chapter
  items: [                          // every book render item, in document order (parts and appendix dividers included)
    { kind: 'index' | 'chapter' | 'appendix' | 'part' | 'references',   // `BookRenderItemKind`, lowercased
      file: string | null,          // '/'-normalized, relative to the project root; null for a divider (a part with `href:` has a file)
      title: string,                // plain text, may be ''; the divider text, or the chapter's `title` metadata, else its first heading
      number: string | null,        // the label the book prints, e.g. '3' or 'A' (`chapter_label_prefix`, `project/book/config.rs:126`); null when unnumbered
      depth: number,                // `BookRenderItem.depth`
      anchor: string | null }       // the marker's `file` value (equal to `file`) when the request carries markers, else null
  ],
  locate: { kind: 'typst-metadata', label: 'q2-book-chapter' }   // pdf request with markers
        | { kind: 'outline' }                                    // fallback
        | null                                                   // epub, typst source, chapter-alone
}
```

- `items` and `active` are present only when `scope` is `book`. `active` is derived by Rust from the active file; the request itself never mentions the active chapter, so two chapters of one book share a `job_id` (R9, Q-9-1).
- **Marker form (`locate.kind === 'typst-metadata'`):** for every file-bearing item, the `.typ` of a `pdf` request contains, immediately after the chapter's first heading, `#context [#metadata((file: "<file>", kind: "<kind>", page: here().page())) <q2-book-chapter>]`. The typst worker compiles once in a world (`compiler.runWithWorld(..., w => { await w.compile(); w.query({ selector: '<q2-book-chapter>', field: 'value' }); w.pdf() })`; the one-shot `compiler.query()` is broken in typst.ts 0.7.0, see Q-10-1) and returns `chapterPages: { [file]: pageNumber }` (1-based physical page, which is what pdf.js's page number is) with the PDF. H9 looks up `items[active].file` in it. A chapter missing from `chapterPages` (a user filter removed its heading) falls back to no navigation and the status says so.
- **Outline form (`locate.kind === 'outline'`):** H9 flattens `pdf.getOutline()` in document order and finds the entry for `items[active]` by **title first**: strip the printed number prefix (`1. `, `A. `, `2.1 ` as typst prints them, i.e. `items[active].number` plus the separator) from each entry's title and compare with `items[active].title`; among equal titles take the one at the same ordinal as the active item among the book's items with that title. Do not count by ordinal among file-bearing items: the outline also holds the **appendix divider and part dividers as entries with no file** (measured: `Appendices` is a depth-0 entry between `3. Two` and `A. Appendix A`), so a pure ordinal lands one entry early after the first divider. If no title matches, no navigation. It resolves the entry's destination through `pdf.getDestination`/`getPageIndex` (measured: pdf.js returns explicit destinations, so `getPageIndex(dest[0]) + 1` is the page).
- Neither form uses named destinations (typst 0.14.2 emits none; see Q-10-1).
- Order of precedence for H9: `chapterPages` if present, else outline, else open at page 1 with a status note.

## Decisions

- No edit to `resources/pandoc-filters/filters/quarto-post/typst.lua`. A Lua edit would be needed only to stamp something from the `quarto-book-item-file` header attribute, which pandoc's typst writer drops (it ignores unknown header attributes); doing it in Rust on the merged AST, before the writer, reaches the same place with no effect on native output.
- The chapter map is computed in the R9 shared core, in the loop that holds `Vec<(BookRenderItem, Pandoc)>` before `merge_book_chapters` consumes it, not from the final AST, so it is available for every request and costs nothing. `kind`, `file`, `depth` and `number` come from the `BookRenderItem` (the printed label through `chapter_label_prefix`); **`title` cannot**: a `BookRenderItem` carries `text` only for dividers, and a chapter's title lives in its paused AST (`meta.title`, else the first `Header`'s plain text, else `''`), so the map is built from the pair, not from the item alone.
- The marker is inserted only when `PrepareOptions.post == RequestPost::CompileTypst`. A `typst` download and native render never see it.
- The marker is placed **after** the chapter's first heading, not before it: the book templates' heading show rules can start a new page (`pagebreak()`; orange-book does), so a marker before the heading would report the previous page. **Measured with orange-book (the default template for a typst book): before the heading the pages come out two too early; after, exact.** A book renders with typst's plain template only if its author overrides the template, so orange-book is the case that matters; the test covers a user-supplied plain template as well.
- File-less dividers (the Appendices divider, parts without `href:`) and the book title page get no marker (nothing to jump to that a chapter does not cover); a part with an `href:` file is file-bearing and gets one like a chapter. A chapter that has no heading (title-less chapter) gets the marker at the top of its content, and the test covers it. The insertion point is `merge_book_chapters` (`merge.rs:272`): it already walks every file-bearing item, stamps its headings (`stamp_headers`) and can insert the `RawBlock` after the first stamped `Header` of the item's body (the header may sit inside a `Div`/`BlockQuote`, which `stamp_headers` already recurses through). Marker form: `merge_book_chapters` gains a parameter (`ChapterMarkers::None | Typst`) rather than a second pass, so the native call site passes `None` and its output cannot change.
