## Goal

The preview server can render a whole book to typst source, PDF or epub for download (chapter-alone downloads are Plan 9's, through Plan 3's `render_chapter_alone`): `q2 preview --ui editor` gets the book half of the hub's Download as, using the native book pipeline.

## Background facts

(2026-10-08 survey, spikes and review; re-check line numbers.)

- **The book path derives its extension elsewhere.** `render_book_single_file` builds `RenderToFileOptions::default()` (`single_file_render.rs:719`) and gets the extension from `determine_output_paths(.., &format.target_format, ..)` (`:722`), which calls `_with_ext(None)` (`render_to_file.rs:631-650`). Options never reach it, a book's own `output-ext` is ignored (unlike single documents), and `typst_target` cannot reach it by itself. `request.rs:114` and `single_file_render.rs:1135` already read `format.output_extension`.
- **Two book entry points already exist.** (a) The browser's request path: `render_pandoc_request` with Plan 3's `BookScope` calls `run_book_request` (`orchestrator.rs:1875`): Pass 1 and the book's `pre_render`, then `render_book_request` (`book/request.rs:35`) with `hooks`, `captures_by_path`, unexecuted counts and `stats.book`; tested natively in `quarto-core/tests/integration/pandoc_request_books.rs` (parity `:306,370`, chapter alone `:474`, scope `:536,557`, progress and cancel `:769,797`, captures `:878-1143`). Both wrap the shared `render_book_core` (`single_file_render.rs:~285`), which takes a `chapter_kind` closure, a `setup` and a `finish`.
- **Gaps in the native tail.** `render_book_single_file` builds its resolver with `site_root = project.output_dir` and calls `apply_project_output_dir_to_options` with `RenderToFileOptions::default()` (`single_file_render.rs:711-722`), and `ResourceCopyFlushStage` allows only the resolver's `site_root` (`resource_copy_flush.rs:94`), so an output-directory option alone would still flush images into the user's `_book/`. It hard-codes `chapter_kind` to `PartialKind::Native` (`:711`) and `hooks: None` (`:~707-709`), discards the accumulated `unexecuted_cells` (accumulated at `:314`), and turns `BookCoreOutcome::Cancelled` into a generic `QuartoError::other("book render cancelled")` (`:~740-783`). `BookRenderHooks::before_chapter` returns `Result<(), Cancelled>` and fires before each chapter only (`core_types.rs:38-52`). The tail in `run_book_single_file_merge` (`orchestrator.rs:1138-1195`) copies resources into `project.output_dir`, calls `write_render_manifest(&project.dir, ..)` (`.quarto/render-manifest.json`) and runs `post_resources` (book delegates to the website llms writer, `.quarto/llms-manifest.json`, `llms_post_render.rs:84`; whether typst reaches it is UNVERIFIED). Typst images are flushed by `ResourceCopyFlushStage` before the compile, so the tail is not needed for the output. Pre-render and post-render scripts run in the CLI (`project/mod.rs:1137`), not the pipeline. Pass 1 is synchronous and rayon-driven (`orchestrator.rs:~1920`), and the pipeline takes `&mut ProjectContext` (the route clones the project as `render.rs:~410` does).
- **Captures.** `PartialKind::Request{captures}` is not cfg-gated and its pause list is the native prefix plus the splice plus `UnexecutedCellCountStage` (`pipeline.rs:556-629`, `:1376-1389`), so it works natively; Plan 6 added the materialize-directory variant. ## Decisions

- **P10-D1 Overlay (E11).** A `SystemRuntime` overlay wrapper (a new module in `quarto-core`) forwards every trait method to the inner runtime except the ones that must see the overlay: it implements `file_read`, `file_read_string`, `is_file`, `is_dir` and `path_metadata` itself (the overlaid chapter answers from the overlay, every other path forwards), because the trait defaults for those route through `self.file_read` and `NativeRuntime` may override them, so plain forwarding would bypass the overlay. Keys are canonical absolute, lexically normalised paths; the route converts from hub-root-relative with the discovered project dir and validates the path with `book_chapter_files`. It serves both Pass 1 and the chapter reads. The client sends the active chapter's current text only; other chapters come from disk (document that unsaved edits elsewhere are excluded when `--allow-edit` is off).
- **P10-D2 Typst source for books.** The route sets the output extension on the `Format` handed to the book path from `typst_target` (`Source`: `output_ext.or("typ")`, skipping the compile; `Pdf`: `pdf`) and `render_book_single_file` passes `Some(&format.output_extension)` to `determine_output_paths_with_ext` at `single_file_render.rs:722`. A book's own `output-ext` is ignored, as today; record it in the docs.
- **P10-D3 Concurrency, cancel and time.** One book download in flight per project; a second returns `409 {"busy": true}`. A drop guard on the handler future sets a cancel flag read by the `BookRenderHooks`, so an aborted request stops at the next chapter boundary; the guard is released when the blocking task ends. The merge tail is bounded by Plan 1's child timeouts. `BookCoreOutcome::Cancelled` gets a distinct error so the route can tell cancel from failure.
- **P10-D4 Native book entry without redirection (E11).** A new `ProjectPipeline::run_book_download` (sibling of `run_book_request`) takes a cloned `ProjectContext` whose `output_dir` is the request directory (this is why the resolver and the resource flush follow without further plumbing), runs Pass 1 and `pre_render` and then `render_book_single_file` into it, with no tail: no resource copy, no render manifest, no `post_resources`, so the user's `_book/` and the render and llms manifests are never touched. `.quarto/` as a whole is not untouched (Pass 1 writes `.quarto/cache/profiles/*` and the crossref filter writes `.quarto/crossref-index.json`); tests assert only that `_book/`, `render-manifest.json` and `llms-manifest.json` are unchanged. The route drives it under `spawn_blocking` (pollster). Pre-render and post-render scripts are CLI-only and are not run (documented). `render_book_single_file` gains an options struct (output extension from P10-D2, output directory, a `chapter_kind` closure, hooks, the capture materialize directory) and returns the accumulated `unexecuted_cells`.
- **P10-D5 Captures (E10).** Per chapter, resolved server-side from the sidecar; the route passes a `chapter_kind` closure using the Plan 6 variant with the materialize directory, with the sidecar key built from the canonicalized hub root and `project.dir`. A chapter without a capture compiles unexecuted and counts into the notice.
- **P10-D6** Progress: none in v1; the status shows "working", then the chapter count from `stats.book`. Preview stays chapter-alone (no whole-book PDF preview); the preview routes send `scope: 'chapter'` explicitly.

## Risks

- Book renders can be slow; cancellation is limited to chapter boundaries and the child timeouts.
- Chapters never opened in the editor may have no capture (unexecuted notice, as on the wasm path).
- The options struct and the scope resolver touch code `q2 render` also uses.
- Whether the book tail's `post_resources` writes anything for typst is unverified; with no tail it is not reached.
