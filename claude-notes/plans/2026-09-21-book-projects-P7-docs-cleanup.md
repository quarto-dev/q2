### Implementation
- [ ] `docs/guides/projects/book.qmd` — usage-focused (per this repo's docs/ convention: document usage, not internals), covering `book.chapters`/`appendices`/`parts`, single-file vs. multi-file output selection, and the DOCX/PPTX/LaTeX scope-out (P3 for the docx/pptx diagnostic; LaTeX per design doc §11, never in scope at all). Document, as known v1 differences from Q1 rather than leaving them for users to discover, **all** of the epic's Known Limitations that are user-visible (list updated by a fifteenth-pass taxonomy review — this docs page is the only user-facing commitment to any of them, so an incomplete list here means real, silent-to-the-user gaps): (1) a Typst book now auto-resolves to the vendored `orange-book` extension when no explicit extension is configured, mirroring Q1's zero-config default (P2/design doc §5) — the remaining, narrower difference from Q1 worth documenting is that overriding to a *different* Typst book extension has no general auto-load mechanism behind it yet; (2) `q2 preview` (per P8, if landed by the time this page is written — otherwise describe the pre-P8 state and update once P8 ships) gets chapter-numbering/title decoration and approximate cross-chapter crossref resolution, but not a merged bibliography preview or single-file-merge preview — and note that a duplicate crossref id across chapters previews cleanly (non-fatal, first-in-book-order-wins) but produces a hard error on a real render; (3) per-chapter subtitle/author-affiliations/date/abstract front matter is not rendered (`bd-ock6cyiy`); (4) **numeric citation styles renumber independently per chapter in multi-file HTML books** — the limitation the epic explicitly prides itself on documenting "unlike Q1's silence" (P6's Decisions), so it must actually reach this page, not just an internal test; (5) no incremental rebuilds for books; (6) both single-file merge and multi-file Pass 2→Pass 3 hold every chapter's data in memory for one render, unverified at 50+ chapters; (7) `q2 preview`'s cross-chapter crossref sweep (P8) recomputes on every preview call for a book project, uncached, adding real per-edit latency on top of Pass 1's own (cached) sweep — unverified at large book sizes; (8) **added by a nineteenth-pass review, missing from this enumeration since this list was last updated in the eleventh pass, before the limitation existed (found in the eighteenth pass)**: Pass 3's resume/write loop is not atomic across chapters — a chapter can be written to disk embedding a resolved number/link into a sibling chapter before that sibling's own resume-and-write happens, so if the sibling's write later fails, the already-written chapter is left referencing content that was never produced, until the next full re-render. The overall render still reports failure (not silent), but the stale partial output on disk is a real, user-visible consequence worth documenting explicitly, matching the treatment every other numbered item on this list already gets.
