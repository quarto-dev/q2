## Why

Every pandoc run on the integration line today is a writer run. Import needs four things from the host side that don't exist yet:
- proof that the wasm build has the I1 readers;
- a way to hand pandoc a file the request doesn't carry: the user's source, whose bytes should not pass through the Rust wasm (I9);
- a way to get `--extract-media` output back (`execute()` returns one file, `ts-packages/pandoc-host/src/execute.ts:179`);
- a shared set of recorded fixtures that P3's Rust tests and this plan's wasm tests both read, so wasm and native are checked against one truth.

It also settles the open docx-reader questions (comment replies, resolved comments, paragraph-mark changes, multi-paragraph comment text) and measures memory for the source cap (I19).
