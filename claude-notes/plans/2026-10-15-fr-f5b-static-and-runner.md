## Goal

`q2 preview --static` on a book whose project format is typst renders the book, serves it, re-renders the whole book when a chapter changes, and shows the render failure in the browser when nothing renders. On an html book it behaves as before. `--static` takes `--to`, `-M` and `--profile` and gives them the meaning they have for `q2 render`. The servable-format gate still refuses epub, docx and pptx (there is no good way to preview them), now judged on the resolved format. `detect_single_input_format` and its helpers, which F5a stopped using, are deleted with their last user. The test runner uses the resolver with `html` as the fallback. The preview pseudo-formats are not touched: `--to q2-preview` and its siblings stay accepted exactly as today (`bd-pseudo-format-to-meaning-vxhyni3t` asks what they should mean).

## Decisions

All from the epic; the plan-level ones:

- **F5b-D1 One path.** Boot render and every watcher re-render build their arguments the same way `q2 render` does (`render_args_for` goes through F5a's `render_once`), with the project as the target. No `-M book-scope` is injected. The flags are bundled once: a prebuilt base `RenderArgs` (the `to`, `-M` and `--profile` values, parsed once at startup; **`RenderArgs` gains `#[derive(Clone)]`**: its fields are clonable, `execution_policy.clone()` is already used at `render.rs:1048`) that `render_args_for` clones and fills with the action's inputs and the execution policy, instead of threading `to` through `start_render` and its call sites. The existing `render_args_for` unit tests are updated to the new form (they do not survive unchanged).
- **F5b-D2 Re-render policy (FR16).** `rerender_action(is_consolidating_book: bool, action: Action) -> Action`: when the project is a Book **and** its resolved format consolidates (in practice typst, the only consolidating format `--static` serves), a `Subset` becomes `Full` (a change to any chapter, to a non-chapter input or to a resource re-renders the whole book; `Ignore` stays `Ignore`); otherwise the action is unchanged, so html, and a typst *website*, keep the per-document re-render. It is applied at the single choke point where re-render arguments are built (`render_args_for` / `start_render`), which every re-render passes through, including the lazy first-view `Subset` of a page with code. Its inputs come from `RenderReport`\'s new fields (F5a-D6), kept in `LastRender` and refreshed by `finish_render`, not from the changed paths or the chapter list, which never matter; so `start_render` takes the two facts (its signature grows) and `finish_render` refreshes them with the rest of `LastRender`. **The action recorded as `in_flight` (and handed back to `finish_render` as `ran`) stays the original `Subset`**: only the arguments are converted. After a `Full` render of a consolidating book `finish_render` sees a `Subset` of one path but a merged output: `output_url_for` finds no match (its synthetic input is `<stem>.qmd`, `single_file_render.rs:1203-1210`) and returns `None`, so the browser gets a plain reload. The function is pure, so it is tested without serving.
- **F5b-D3 Failure page.** When a render yields no outputs the viewer serves a page showing the render failure (the diagnostics that already reach the terminal), for every format, instead of the missing-index page. This covers re-renders; a boot-time abort exits the process (F5b-D6).
- **F5b-D4 Servable-format gate.** `check_servable_format` judges the resolved project format together with `--to` (and a scalar `-M format:`), so an epub, docx or pptx project, or request, is refused up front. html, revealjs and typst are servable. The refusal stays: a browser has no useful way to show an epub, and a "download it" landing page is not part of this epic (do not add one). **It is called from two places today (`execute`, `:103`, on `--to` only; `run`, `:303-307`) and becomes one call:** the gate runs before any render, so it first discovers the project with the selection and calls the resolver (`resolve_project_format` with a `Full` request for a directory or a file inside a project, `resolve_document_format` for a standalone file), with the base `-M` overlay applied so that a scalar `-M format:` reaches it; the `execute` call is removed. **If the resolver itself errors at that point (a profile that does not exist, the FR6 error), the gate does not fail: it lets the render report the error, so the more specific message wins.** `detect_single_input_format` is deleted here, with `read_single_input_content`, `format_key_from_frontmatter`, `format_keys_from_frontmatter` and `resolve_format` if nothing else uses them (F5a left them for this plan). Pseudo-format `--to` values are not judged here beyond what `resolve_format` and the identifier check already do (`--to q2-preview` resolves to html and passes, as today). The function F8 reuses for the live viewer is this one.
- **F5b-D5 The runner** (`quarto-test`) calls the resolver; the fallback is `html`; the runner passes a format override only when the spec names a format (it no longer always overrides, which would bypass FR1); fixtures that relied on the typst default get an explicit `format:` or `--to` (list them in the Handoff log).
- **F5b-D6 `--static` takes the render flags (FR20).** `Commands::Preview` gets `-M/--metadata` (repeatable) and `--profile` (comma-separated or repeated), both `requires = "static_mode"` like `--to` (F8 relaxes this: it moves the three flags out of the `--static`-only set); `StaticArgs` carries them; the base `RenderArgs` (F5b-D1) holds them, so the boot render and every watcher re-render see them. `-M` is parsed once at startup with F1's function: a malformed value fails before anything renders. `--profile` is also handed to the config readers in `quarto-preview/src/config.rs` (the two this plan calls, `:154` and `:176`, and the two others in the same file, `:217` and `:279`, so the file follows one rule; the live viewer's callers, `preview.rs:234, 246`, pass no selection until F8), so the whole session uses one selection. **New code reads the profile through the runtime it already has and adds no inline `NativeRuntime::new()`**: F8 replaces the existing inline runtimes (`preview_static.rs:315, 333, 340, 644`) with its runtime factory, so keep those call sites easy to find. **`-M book-scope:chapter` on a Book project is the FR6 error and ends the process:** the boot render aborts and the process exits 1 with the message (`exit_with_abort`, `:366-378`; the flag is fixed for the session, so a failure page would never be reachable); this holds when the argument is a directory and when it is `ch1.qmd` inside the book, because the file is mapped to the project root (`:313-323`) and the target is `Full`; the gate (F5b-D4) must swallow the resolver's error so this message, not a gate error, is what the user sees. The same flag on a non-book project, or on a single document outside a project, is the FR5/FR6 info. The help text is the one shared with `render` (F1-D5). The Preview `--to` help text (`main.rs:~355-357`) is corrected here.

## Risks

- `preview_static.rs` is not hot, but its tests are timing-sensitive; reuse the existing harness and do not add sleeps. `main.rs` is hot (F1 `-M`, F3b flag removal, F5a, F8 later), and F8 touches the inline runtimes and flag definitions this plan adds: keep the diff to those lines small.
- The runner audit (5b.5) can touch many fixtures; if more than a handful depended on the typst default, list them in the Handoff log and fix them in a separate commit.
- The whole-book re-render policy only helps formats that consolidate; do not widen it to html (the html limitation has its own strand).
- Typst fixtures skip when the binary is absent: on a machine without typst the typst cases are silent; CI installs it. Say what could not be tested rather than counting a skip as a pass.
- Lazy execution on `--static` is driven by html page views, so code in a typst book's chapters stays inert; recorded, not fixed.
