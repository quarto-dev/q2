## Goal

The quarto-core pieces every typst preview or download needs: choosing the typst output (`pdf` or source), splicing captured cell outputs into the AST without kernels, counting unexecuted cells, and rendering into a per-request directory under the discovered project.

## Background facts

- **Typst root.** `TypstCompileStage` runs `typst compile --root <ctx.project.dir> <output-dir>/<doc>.typ` (`typst_compile.rs:245-247`). typst refuses a source outside its root, so an OS-temp output directory fails with `Q-21-3`. The root is the *discovered* project directory (`ProjectContext::discover`, `project/mod.rs:2000-2045`: for a doc with no `_quarto.yml` it is the doc's parent), which can differ from the hub root. `q2 render a.qmd --to typst --output-dir <proj>/.quarto/preview-out/x` works (0.37-0.44 s over five runs). `render_document_to_file` takes `Option<&ProjectContext>` (`render_to_file.rs:96-141`).
- **Extension.** For a single document the extension is derived at `render_to_file.rs:319-345` (`typst_output_ext`), and `TypstCompileStage`\'s skip reads `ctx.format.output_extension` (`typst_compile.rs:91-95`); nothing else reads `output-ext` (grep-checked). `q2 render` with `output-ext: typ` writes `.typ` and no PDF; `output-ext: typst` writes `doc.typst`. The book path derives its extension separately (Plan 10).
- **Captures.** `CaptureSpliceStage` splices captured outputs into the AST keyed by `(structural_hash, occurrence_index)` (`engine/capture_splice.rs`), so edits keep unchanged cells\' outputs; `materialize_capture_files(runtime, doc_dir, files)` already takes the directory, but the stage writes into `doc_ast.path.parent()` (`:174-203`, `:184`; `capture_files.rs:156-169`). `build_pandoc_prefix_stages(captures)` already inserts it (`pipeline.rs:556-566`; works for typst) but `build_pandoc_pipeline_stages` hard-codes `Vec::new()` (`:667-669`; about 20 test callers; production caller `render_qmd_to_pandoc`, `:433-439`, from `render_to_file.rs:441`). `PartialKind` is `Native | Request{captures}` (`pipeline.rs:1376`); adding a field to the struct variant breaks about 8 constructors (`request.rs:62,76,82,84`; `single_file_render.rs:1127`; `pipeline.rs:7059,7076,7106`). `ReplayEngine` is the wrong tool: it fails on edited text (`replay.rs:130-141`) and writes no files. `ExecutionPolicy::None` returns before any engine runs for non-notebook documents (`engine_execution.rs:382-393`). Captures are recorded under the `q2-preview` format (`preview_record.rs:150`).
- **Unexecuted cells.** `UnexecutedCellCountStage` is absent from the native stage list (it runs only in the pandoc-request list, `pipeline.rs:571-586`); `RenderToFileResult` has no `unexecuted_cells` field; `ctx.unexecuted_cells` is available in `finalize_rendered_output` (`pipeline.rs:1273`).
- **Preview directory facts.** `.quarto/` is hidden, so `ProjectFiles::discover` skips it (`quarto-hub/src/discovery.rs:301-318`); watcher events for unindexed paths are dropped (`sync.rs:520-528`, `server.rs:2169-2190`) but `PreviewBroad` raises them for png/jpg/svg by extension alone (`quarto-hub/src/watch.rs:260-296`). `.quarto/preview-out` is not gitignored (`storage.rs:521-527` ignores only `.quarto/hub/` and is the precedent for a self-written `.gitignore` of `*`). `q2 preview` keeps hub data in a temp dir (`storage.rs:458-465`), so its hub writes nothing into the project without `--allow-edit`; renders themselves do write under `.quarto/` (pass 1 caches profiles; the pandoc crossref filter writes `.quarto/crossref-index.json`).

## Decisions

- **P6-D1 (E8)** `RenderToFileOptions.typst_target: Option<TypstTarget>` (`Pdf` | `Source`). `Pdf` forces the `pdf` extension regardless of `output-ext` (the browser's `typst-pdf` never refuses); `Source` uses `output_ext.or("typ")`, except that an explicit `output-ext: pdf` also maps to `typ` (otherwise `is_typst_compile_ext` would run the compile, `typst_compile.rs:91`); a literal `output-ext: typst` is kept, as hub-client's `withOutputExt`; `Source` skips the compile. Unset keeps `q2 render` unchanged.
- **P6-D2 (E10)** Captures come from the sidecar only; capture plot files are written into the request directory, never beside the source; typst and pandoc resolve them there (typst via the Plan 2 resolver rule, pandoc via `--resource-path`). Policy stays `ExecutionPolicy::None`.
- **P6-D3 (E9)** Typst renders go to `<ProjectContext::discover(abs_path).dir>/.quarto/preview-out/<uuid>/`, removed by a guard inside the blocking closure, swept at server start (age cutoff), gitignored; a read-only project gets a clear error; no fallback. Rejected: widening typst's `--root` (lets raw `{=typst}` `#read` far beyond the project). Non-typst formats keep an OS temp dir (Plan 2 fixed images there).
