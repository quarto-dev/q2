Caret position from a Range. Every rendered node carries a data-off="start-end" source span. A leaf's own text sits in a child span whose only child is a text node. To draw the caret at a source offset, the branch finds the smallest leaf span containing it, converts the offset into a character index within that leaf's text, then builds a collapsed DOM Range at that index with setStart and setEnd on the text node. The first rect from getClientRects() gives the exact inter-character x position and the line height. If the collapsed rect comes back empty, which some engines do at a text node's very start or end, it falls back to the left or right edge of the text span's bounding box. The rect is converted from viewport space into the scroll container's space, and an absolutely positioned div is placed there. For leaves with no text, such as a space or a math glyph, it uses the leaf element's own box edge. Offsets that fall in syntax with no glyph, such as the * of an emphasis, resolve to the nearest leaf edge in source order.

Pointer to position, without jumping. The problem it was solving is that elementFromPoint snaps to whatever box is under the pointer. Over padding, margins or the gap between two boxes, that is a container, and a container's edges can be a paragraph apart in source, so the caret would leap. The fix is to never resolve to a container. The branch keeps a cached list of leaves with their bounding rects, and picks the nearest one by vertical distance first, which selects the row, then horizontal distance within that row. Once a leaf is chosen, if it has text, the x coordinate is clamped into the nearest line rect of that text and caretPositionFromPoint, or caretRangeFromPoint on WebKit, is called at that clamped point. That returns the text node and character index, which is mapped back to a source offset. Clamping means a pointer over a label or padding slides along the text instead of snapping to an edge. If the hit test misses the text node, it falls back to the nearer edge of the line.

Drag stability across rows. During a drag the anchor's leaf is remembered. When the pointer is in the margin between rows and two rows tie on vertical distance, the row that vertically overlaps the anchor's leaf wins, so a wobbling horizontal drag does not flicker between rows. That preference only applies when the pointer is outside every row. Inside a row, horizontal distance alone decides, otherwise the drag head could never leave the anchor's node.

Caching. Leaf rects are computed once per render and invalidated on scroll and resize, so a pointer move costs one scan over the leaves plus at most one hit test.
